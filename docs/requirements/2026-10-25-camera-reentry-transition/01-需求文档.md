# 退出单机后立即重进视野拉远修复需求文档

## 背景

用户在单机牌桌完成一局后退出大厅，立即再次进入单机模式。相机没有回到玩家机位，而是停在远景，桌面显得很小、远离玩家。截图显示人偶、桌面和底牌都在，但摄影机明显退到大厅视角。

## 根因

`PokerScene` 维护了一个 `transitionPromise`：

- `toLobby(1900ms)` 开始时设置 `transitionPromise`；
- 用户在动画完成前重新进入单机；
- `enterTable(1350ms)` 发现 `transitionPromise` 仍存在，直接 `return this.transitionPromise`；
- 实际上返回的是上一段 **toLobby**，相机继续飞向大厅远景；
- 旧动画完成后把 `mode` 设置成 `lobby`，但游戏已经重新开始，于是牌桌在运行、相机却停在大厅。

这是典型的异步转场竞态。

## 目标

- 退出后立即重进单机，相机必须回到正常英雄机位；
- 新的进桌转场必须取消旧的离桌转场；
- 旧转场完成时不得覆盖新场景的 mode / camera；
- 桌面、视角、底牌恢复正常；
- 手机端和网页端一致。

## 需求点

- **R1** 相机转场增加单调递增 token。
- **R2** `toLobby` 和 `enterTable` 每次开始都使 token+1。
- **R3** 转场 update 回调只在 token 仍是当前值时更新相机。
- **R4** 转场完成回调只在 token 仍是当前值时设置 mode/清空 promise。
- **R5** `enterTable` 不再复用正在运行的 toLobby promise。
- **R6** 完成时强制设置目标相机位置/FOV/look，避免停在插值中间。
- **R7** 不改变正常首次进桌和正常返回大厅动画。

## 非目标

- 不改变英雄座位/桌面建模；
- 不改变相机操作手势；
- 不改变大厅动画；
- 不处理 GPU 性能。

## 验收标准

- **AC1** 从 hero 机位调用 toLobby 后120ms 调用 enterTable，最终 mode=hero。
- **AC2** 最终相机位置与 heroCamBase 距离 <0.01。
- **AC3** 旧 toLobby 完成后不会把 mode 改为 lobby。
- **AC4** 正常首次进桌仍能进入 hero。
- **AC5** 正常退出仍能回到大厅。
- **AC6** 页面无 JS 错误。
- **AC7** Android 1.0.97 构建通过。
- **AC8** 真机快速点击退出/进入需人工复测。

## 风险

- 旧动画仍会在 activeAnimations 中跑完，但 update 会被 token 守卫跳过；
- 快速多次切换会产生多个已取消的 promise，但每个都很快结束；
- 真机触摸节奏可能不同，需要复测。
