# 播报队列与语速自适应测试报告

> 版本：1.1.7（versionCode 113）  
> 日期：2026-10-26  
> 环境：Edge/Playwright；本地/生产；无真机听感

## 1. 根因

1.1.6 的 `speak()` 每来一条新动作就递增 `speakSequence` 并停止当前音频：

- 上一位姓名刚播完，下一位动作到来；
- 上一位操作音频被取消；
- `lastSpeak` 400ms 还会丢弃快速动作；
- 固定 playbackRate，无积压加速；
- 结算文本 `speakText` 可能被后续 TTS 取消。

## 2. 修复

- `speechQueue` FIFO；
- 一条播报=称呼音频+动作/金额包；
- 当前条目完整 `await` 后才取下一条；
- 新动作只入队，不取消当前；
- 语速：
  - 无积压 1.06；
  - 1条 1.16；
  - 2条 1.34；
  - 3条 1.52；
  - 4+条 1.70；
- 积压增加时对正在播放的 AudioBufferSource 实时提速；
- 结算/成就文本通过 `/api/voice/phrase` 生成同音色音频，并入同一队列；
- 单机结算新增赢家/底池播报；
- 在线结算 `announceSettlement` 继续入队。

## 3. 测试结果

生产队列注入：

```text
speak('raise',20,'阿凯')
speak('call',20,'小明')
speak('check',0,'小红')
speakText('阿凯赢得底池 60')

order:
  阿凯         rate 1.70
  en_raise...  rate 1.70
  小明         rate 1.52
  en_call...   rate 1.52
  小红         rate 1.34
  check        rate 1.34
  阿凯赢得底池60 rate 1.16

queue = 0
busy = false
pageerror = 0
```

说明：

- 三个玩家全部按顺序播完；
- 没有取消上一位；
- 速率随积压递减；
- 结算文本排最后，没有丢。

## 6. 未覆盖/风险

- 真机连续快节奏听感未实测；
- 队列积压很多时总延迟仍会存在（但不再丢语音）；
- 服务端阶段TTS生成约2秒，结算/长文本首次可能等待；
- 队列没有设置上限，极端刷动作会排长队。

## 7. 结论

**顺序、完整性、自适应语速、结算文本入队均通过代码/生产注入测试。**
