# 01 需求文档：HTTPS 网址打开 + 语音说话（临时桥接）

- 日期：2026-10-27（Asia/Shanghai）
- 目标 URL（用户提供）：`https://192.144.159.220:8080/play`
- 当前临时 URL：**已停止**（localhost.run 免费隧道反复超时/轮换，无当前可用地址）
- 状态：**临时桥接方案已停止**；稳定生产 URL 仍阻塞（无服务器 SSH/域名/TLS）
- 历史测试入口：`https://56f32046dd5f12.lhr.life/play`（仅作当时证据，已 502）

## 1. 背景与问题

用户要求「用尽一切办法让游戏能够使用网址打开，让用户能够进行语音说话」，
并给出 `https://192.144.159.220:8080/play`。

实际探测：

| 检查 | 结果 |
|---|---|
| `https://192.144.159.220:8080/play` | TLS 握手失败：`schannel: SEC_E_INVALID_TOKEN (0x80090308)` |
| `http://192.144.159.220:8080/play` | 200，生产页面（本轮探测时版本 1.1.14） |
| 443 端口 | 关闭 |
| 服务器 SSH | `dezhounight_deploy` key 被拒；无 `DEPLOY_PASS` |
| 域名/TLS | 无 |

原因：8080 是 Node 的**明文 HTTP**，不是 HTTPS；在没有服务器权限的情况下无法给
这个 IP:8080 换上受信任证书。iOS 的 `getUserMedia`/语音要求安全上下文（HTTPS 或
localhost），所以必须另做一个 HTTPS 入口。

## 2. 目标与成功标准

### 目标

- **G1**：给用户一个 HTTPS URL，能打开生产牌桌，而不是 TLS 报错。
- **G2**：该 URL 是安全上下文（`isSecureContext=true`），可以取得麦克风。
- **G3**：语音 WebSocket 中继 `wss://<host>/api/voice-relay` 能建连，用户可在房间里说话。
- **G4**：首次加载后缓存牌桌 HTML，第二次打开明显更快。
- **G5**：不修改生产服务器、不暴露服务器凭据；明确这是临时桥接，不是生产 TLS。

### 非目标

- 不把 `https://192.144.159.220:8080` 真正变成 TLS（需要服务器权限 + 可信证书）。
- 不提供 24×7 稳定域名；当前是本机 + 免费 SSH 隧道。
- 不做 App Store/TestFlight；不做 PWA 离线（本轮 loader 下旧 SW 未注册）。
- 不验证真机双人语音音质；只验证安全上下文、麦克风轨道、WSS 建连。

## 3. 用户场景

1. 用户在 iPhone Safari 打开 `https://42f2345c1cb927.lhr.life/play`；
2. 首次显示「正在进入牌桌」，分块加载约 20–30 秒（视网络）；
3. 页面弹出「添加到主屏幕」引导，可关闭；也可继续在 Safari 玩；
4. 登录/游客进入，加入房间；点语音按钮，允许麦克风；
5. 另一名用户打开同一 URL、加入同一房间；双方通过 WSS 中继说话；
6. 第二次打开命中 localStorage 缓存，约 2 秒进入游戏。

## 4. 需求点

| 编号 | 需求 |
|---|---|
| R1 | 提供一个可访问的 HTTPS URL，返回生产牌桌页面 |
| R2 | 页面为安全上下文（`window.isSecureContext=true`） |
| R3 | `navigator.mediaDevices.getUserMedia({audio:true})` 返回有效音轨 |
| R4 | `wss://<host>/api/voice-relay` 可 101 升级，语音中继可用 |
| R5 | 第二次加载命中缓存，不能每次重复下载 1.4MB |
| R6 | 不能出现 Serveo/Pinggy 那类浏览器警告页；URL 直接进游戏 |
| R7 | 临时入口不能要求改生产服务器、不能要求域名/证书 |
| R8 | 明确隐私边界：TLS 在第三方隧道终止；只允许测试账号，不用真实密码 |

## 5. 方案概述

```
iPhone Safari
  https://56f...lhr.life/play
        │  TLS（localhost.run 终止）
        ▼
localhost.run SSH 隧道
        │
        ▼
Windows 本机代理 127.0.0.1:18080
  ├─ /play           -> 3.5KB loader
  ├─ /__chunk/meta   -> {total, count}
  ├─ /__chunk/N      -> 128KB gzip 分块（约 36KB wire）
  ├─ /api/*、/voice/* -> 生产 192.144.159.220:8080
  └─ /api/voice-relay -> 生产 WSS 中继
        │
        ▼
生产 Node HTTP 8080（1.1.14）
```

- 生产单文件 HTML 约 1.35MB；免费隧道单响应会截断到约 200–300KB，因此不能直接代理。
- 本机代理缓存生产 HTML，按 128KB 分块并用 gzip 发给隧道；loader 拼回后
  `document.write` 成真正的游戏页面。
- 首次加载后把 HTML 存入 localStorage；第二次直接写页面。
- 语音走同源 WSS；隧道把 Upgrade 透传到生产。

## 7. 依赖与风险

| 项 | 风险 | 处理 |
|---|---|---|
| 本机 Windows | 关机/睡眠/网络断，URL 失效 | 仅测试用；长期需服务器域名 |
| localhost.run 免费隧道 | URL 会变、可能 502、无 SLA | 本轮实测 502 后重启换 URL；文档记录 |
| TLS 终止在第三方 | 隧道方可看到明文登录 | 只用测试账号；正式域名必须自建 TLS |
| 单文件 1.35MB | 免费隧道截断 | gzip + 128KB 分块 + localStorage 缓存 |
| Service Worker | loader 在 load 后写入，旧 SW 注册不触发 | 语音不依赖 SW；离线不在本轮范围 |
| 首载 20–30s | 用户等待 | loader 进度条；二次缓存 2s |
| 公开 URL | 任何人可访问游戏入口 | 仅发给测试者；不要公开张贴 |

## 8. 待确认问题

1. 这个临时 URL 是否只用于内测？若是，可直接使用；若要公开给大量用户，必须走域名+TLS。
2. 是否提供服务器 SSH/`DEPLOY_PASS` 和域名？有的话可做正式 HTTPS，不再依赖本机隧道。
3. 是否接受第三方隧道终止 TLS？不接受则不能用当前方案，需等正式证书。
