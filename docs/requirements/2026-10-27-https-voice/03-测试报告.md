## 4. 问题与处理

### D1 原始 HTTPS URL 不可用（约束）

- `https://192.144.159.220:8080/play` 的 TLS 握手失败；8080 是 Node HTTP。
- 处理：另起 HTTPS 入口，保留 HTTP 生产源站；明确告知用户原 URL 不能直接用。

### D2 免费隧道限制（已绕过）

- Cloudflare quick tunnel：HTML 被 DNSPod webblock 302（本网络不可用）。
- Serveo：浏览器警告页 + 大响应截断。
- Pinggy：浏览器警告页 + 60 分钟限制。
- localhost.run：无警告页，但单响应截断到约 200–300KB。
- 处理：本机代理把 1.35MB HTML 缓存后按 128KB gzip 分块，loader 拼回；
  localStorage 缓存二次加载。

### D3 Service Worker 未注册（已知限制）

- loader 在 `load` 之后 `document.write`，生产页面的 `window.load` 监听不触发，
  SW 不注册；离线/PWA 缓存不可用。
- 语音走 `getUserMedia + WSS`，不依赖 SW；本轮目标是网址+语音，不把离线算通过。

### D4 隧道不稳定（临时）

- 旧 localhost.run URL 在测试过程中 502；重启 SSH 得到新 URL。
- 处理：文档记录当前 URL；失效后需重启隧道；长期方案必须域名+服务器 TLS。

### D5 首载 20–30 秒（体验限制）

- 1.35MB 经海外免费隧道分块；batch 4 后仍需约 20–30 秒。
- 处理：loader 进度条；localStorage 缓存后 1,991ms；仅适合内测。

## 5. 未覆盖项

- 真机 iPhone Safari 的麦克风授权、回声、延迟、双人听感。
- 两名真实用户同时进房说话的端到端音频。
- 24 小时/多人并发稳定性。
- 生产域名/TLS/ICP；当前仅为第三方隧道。
- PWA 离线（SW 未注册）。

## 7. 结论

- **临时 HTTPS 入口可用**：页面加载、`isSecureContext`、麦克风音轨、WSS 语音中继、
  二次缓存均通过真实执行。
- **原始 `https://192.144.159.220:8080/play` 不可用**，这是明文 8080 + 无服务器权限
  的硬约束；不能宣称这个确切 URL 已修好。
- **当前 URL 是临时桥接**：依赖本机、localhost.run、免费隧道；会失效/变慢；
  TLS 在第三方终止，登录凭据存在隐私风险。
- 正式给用户使用前，必须换成自己的域名 + 服务器 TLS/命名隧道；本轮不把临时 URL
  当作生产发布。
