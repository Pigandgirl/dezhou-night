## 3. 用户操作步骤

1. iPhone Safari 打开 `https://42f2345c1cb927.lhr.life/play`；
2. 首次显示「正在进入牌桌」，约 20–30 秒（分块加载），等进度完成；
3. 出现「添加到主屏幕」引导可关闭；不安装也可继续；
4. 登录（**只用测试账号**）或游客进入；加入房间；
5. 点语音按钮，允许麦克风；对方打开同一 URL、进同一房间，即可对讲；
6. 第二次打开约 2 秒（浏览器 localStorage 缓存）。

如果打开报 502/无法访问：隧道已掉，需要重新起隧道（见 `02-测试方案.md` 命令），
会得到一个新的 `https://xxxx.lhr.life` URL；旧 URL 不保证恢复。

## 4. 安全与合规提醒（重要）

- 当前 TLS 在 **localhost.run 第三方**终止，本机代理再以 **HTTP** 转发到生产；
  登录密码、Token、语音数据经过第三方隧道，存在被查看的风险。
- **只用测试账号/测试房间**；不要用真实账号密码，不要发管理员账号。
- 不要把该 URL 公开张贴；任何拿到 URL 的人都能访问游戏入口。
- 这不是正式发布，不能替代域名 + 自有 TLS + 生产服务器部署。

## 5. 遗留问题与风险

1. **原始 `https://192.144.159.220:8080/play` 无法直接修好**：8080 是明文 HTTP，
   没有服务器 SSH/域名/证书；要修必须上服务器改 TLS 或加反向代理。
2. **临时 URL 不稳定**：免费 localhost.run 隧道无 SLA，可能 502、URL 变化；
   依赖本机开机和网络。
3. **首载 20–30s**：1.35MB 单文件经海外隧道分块；二次缓存 1,991ms。
4. **真机双人语音未验证**：只验证了安全上下文、假设备音轨、WSS 101；
   回声/延迟/双人听感需真机复验。
5. **SW/离线不可用**：loader 在 load 后写入，生产旧 SW 不注册；语音不依赖 SW。
6. **生产版本变化**：本轮生产为 1.1.14；若生产更新，代理缓存 5 分钟内刷新，
   首载内容可能随版本变化。

## 6. 发布建议

### 现在可以

- 内部测试：把临时 URL 发给测试者，用测试账号进房验证语音；
- 验证：页面能开、麦克风授权、双方能听到、二次加载变快。

### 正式给用户前必须做

1. 域名 + 服务器 TLS（Caddy/Nginx + Let's Encrypt，或 Cloudflare 命名隧道）；
2. 不再依赖本机/免费隧道；
3. 真机 iPhone 双人语音、弱网、回声测试；
4. 修复 SW 注册/离线（或接受 PWA 只在线）；
5. 评估隐私与登录安全，使用自有 TLS 终端。

## 7. 最终结论

- **用户的要求在“临时可用”层面达成**：有一个 HTTPS 网址能打开游戏，麦克风 API 可用，
  语音 WSS 中继可建连；二次加载有缓存。
- **但原始 IP:8080 的 HTTPS 不可用**，当前 URL 也不是稳定生产入口；不能对用户宣称
  “永久 HTTPS 已上线”。
- 当前交付定位：**内测/临时验证**。要做正式 HTTPS + 语音，仍需服务器权限与域名证书，
  或一个稳定的命名隧道/自有反向代理。
