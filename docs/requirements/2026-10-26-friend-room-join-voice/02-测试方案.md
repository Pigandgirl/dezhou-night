# 好友房加入与播报队列测试方案

## 用例

| 编号 | 需求 | 步骤 | 预期 |
|---|---|---|---|
| T-FR-01 | R1 | 输入口令加入进行中8人房 | 立即显示加载层/进度 |
| T-FR-02 | R2/R3 | 5人在座，第6人加入 | 等待层显示名字；本手后入座 |
| T-FR-03 | R4 | 入座后检查 state/scene | seats=6、玩家模型对齐 |
| T-FR-04 | R5 | 8人房5→6→7 | 均可加入 |
| T-FR-05 | R6 | 满员5人房第6人 | 观战+名字 |
| T-FR-06 | R7 | 5条播报积压 | 1.95倍并全部播完 |
| T-FR-07 | R8 | 结算文本 | 排在动作后播报 |
| T-FR-08 | AC9 | 10轮朋友/匹配 | 10/10通过 |
| T-FR-09 | AC10 | 构建部署 | 1.1.8 |

## 10轮设计

- 第1-5轮：好友房，8座位，5人开局，第6人中途加入；
- 第6-10轮：在线匹配，5人开局，第6人中途加入；
- 每轮驱动当前手结束，等待下一手，校验第6人是否真正入座。

## 环境

- 本地 server；
- 8-9 个 QA 账号；
- `TURN_MS=1500`、`NEXT_HAND_MS=600`；
- Playwright 1200×600；
- 无真机音频听感。
