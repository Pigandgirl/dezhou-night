# 在线牌局体验升级优化方案

> 状态：需求与方案评审版  
> 日期：2026-10-25  
> 目标版本：待排期（1.0.99+）  
> 原则：先方案、再开发、后测试；验收不通过不部署。

## 1. 目标

这一轮不是单点修复，而是对在线牌局的「信息可读性、操作焦点、语音质量、后台连续性、观战能力」做一次整体升级。

优先级：

1. **P0 牌局隐私与结算正确性**：全弃牌不亮赢家底牌；结算统计完整。
2. **P0 筹码与操作焦点**：玩家剩余筹码、本手下注、底池清楚；当前操作玩家有聚光灯与轻量镜头聚焦。
3. **P0 专业术语语音**：中文与英文术语随机混播，动作字幕始终可读。
4. **P1 语音网络优化**：4 人同时开麦不卡顿、不抖动、不拖垮在线连接。
5. **P1 后台连续在线**：切到其他 App 3-60 秒回来自动恢复，不误判离线。
6. **P1 观战自由视角**：筹码归零后围绕牌桌自由观战，只可看公共信息。
7. **P2 操作历史/牌局回放**：本轮只整理接口与数据结构，不开发完整回放。

## 2. 当前基线（代码事实）

### 2.1 结算

- `server/lib/game-engine.js#buildSettlement()` 无论 `showdown` 真假，都把未弃牌玩家 `hole` 放进 settlement。
- `src/hud.js#showSettlement()` 无条件渲染 `row.hole`，所以全弃牌也会亮出赢家底牌。
- 全弃牌时 `showdown=false`，没有真实摊牌，亮底牌属于信息泄露。
- 结算摘要目前没有全桌总筹码字段，需要由 `state.seats[].stack` 聚合。

### 2.2 筹码与焦点

- 3D 名牌只显示名字/状态/筹码，字号小，桌边筹码叠与下注叠的区分不够明显。
- `scene.setTurn(seat)` 只切换人偶状态，不做镜头聚焦或聚光灯。
- 当前只有 `updateCamera()` 的指针视线偏移，没有「当前操作玩家」焦点状态机。
- 当不是本人操作时，没有统一的暗化规则。

### 2.3 语音

- 当前语音是 16kHz 单声道 PCM16，通过 WebSocket relay 发送，每路约 256kbps。
- 4 人同时开麦时，每人上行约 256kbps，relay 还要向其他 3 人转发，网络与 CPU 压力都很大。
- 不是 Opus 编码，没有 VAD/DTX/静音抑制，没有自适应码率，也没有丢包隐藏。
- 这是「4 人开麦就网络波动」的主要原因之一。

### 2.4 后台在线

- SSE `/api/rooms/:code/events` 每 15 秒心跳。
- SSE `req.on('close')` 会立即把 `player.online=false`、`voiceLeave`、`broadcastPlayers`。
- 房间在线状态直接依赖 SSE 连接存在；App 切后台导致 WebView 连接暂停/关闭时，服务端会立即认为玩家离线。
- `PRESENCE_TTL=45s` 只影响 `/api/presence` 统计，不影响房间座位在线状态。
- 因此 3-4 秒后台就可能出现「已断开」。

### 2.5 观战

- `spectatorState()` 已经会清空 `hole/bestCards/score/handDetail` 并设置 `settlement:null`，这是隐私基础。
- 客户端没有自由视角，筹码归零后仍固定在自己的机位。
- 观战没有独立的「自由镜头」UI、边界限制和复位按钮。

## 3. 方案总览

```text
┌─────────────────────────────────────────────┐
│ P0 结算隐私 + 筹码信息 + 操作焦点 + 术语语音 │
│ P1 语音编码/网络 + 后台连续 + 观战自由视角   │
│ P2 操作历史/回放（本轮只设计，不开发）        │
└─────────────────────────────────────────────┘
```

## 4. P0：全弃牌结算隐私

### 4.1 规则

- `showdown=false`（所有其他人弃牌）：
  - 服务端 settlement **不返回任何人的 hole**；
  - 服务端不返回 winner 的 bestCards/score/handName；
  - 客户端不渲染底牌、不渲染最佳五张；
  - 3D 赢家底牌保持牌背或直接收走；
  - 结算只显示：赢家名字、赢得底池、其他玩家弃牌、总筹码。
- `showdown=true`：
  - 仅在结算状态公开参与摊牌玩家的底牌；
  - 已弃牌玩家不公开底牌；
  - 观战者永远不公开底牌。
- 底牌隐私由服务端裁剪，客户端隐藏只作为第二道防线。

### 4.2 数据结构

```text
settlement: {
  showdown: boolean,
  pot: number,
  totalChips: number,
  contenders: [
    { name, won, stack, hole?: Card[], bestCards?: Card[], handName?, ... }
  ],
  folded: string[],
  winners: [{ name, amount }],
}
```

`hole/bestCards/handName` 只在 `showdown && !folded` 时存在。

### 4.3 交互

- 结算标题：`本手结束 · 全部弃牌`。
- 赢家行显示：`XXX 赢得底池 +N`，不显示底牌区域。
- 继续按钮保留：所有在线玩家可点「继续下一把」。
- 总筹码摘要：`全桌总筹码 X · 本手底池 Y · 筹码归零：...`。

## 5. P0：筹码与信息层级

### 5.1 信息优先级

```text
第一层：底池、当前操作玩家、当前下注
第二层：每个玩家的剩余筹码
第三层：自己的底牌、动作按钮
第四层：非操作玩家的历史动作文字
```

### 5.2 玩家名牌

每个玩家名牌至少显示：

```text
名字
剩余筹码 124
本手已下注 12
动作标签：ALL IN / 跟注 / 过牌 / 弃牌
```

- 剩余筹码用高对比数字，不用缩写（K 只在超过 10000 时使用）。
- 当前下注单独一行，与剩余筹码区分。
- 弃牌玩家名牌降低不透明度，但保留可读性。
- 当前操作玩家名牌高亮描边、聚光、轻微上浮。
- 底池数字常驻，字体不小于当前操作玩家名字。
- 3D 筹码叠上保留金额标签；如果标签太小，用 HUD 常驻小面板替代。

### 5.3 自己回合 vs 非自己回合

| 状态 | 自己的信息 | 操作按钮 | 其他玩家 |
|---|---|---|---|
| 自己回合 | 完整显示筹码、底牌、可行动作 | 显示 | 聚焦当前操作者（自己） |
| 他人回合 | 自己的底牌和筹码保留，但视觉降权 | 隐藏 | 当前操作者聚光，其他暗化 |
| 结算 | 结算面板 | 继续/退出 | 公开信息，无操作焦点 |
| 观战 | 无自己的底牌 | 无 | 公共牌+操作焦点 |

### 5.4 暗化规则

- 非操作玩家名牌：透明度 0.55-0.65。
- 非操作玩家动作文字：透明度 0.4-0.5。
- 底池、公共牌、当前操作玩家：保持 1.0。
- 自己的操作按钮：非自己回合隐藏，不用 disabled 常驻。
- 暗化用 250-350ms 过渡，不瞬间跳变。
- 提供「低动态模式」：关闭镜头跟随和聚光闪烁，仅保留名牌高亮。

## 6. P0：当前操作玩家聚焦

### 6.1 状态机

```text
idle → actorFocus(seat) → hold → returnNeutral
```

- `actorFocus`：摄像机轻微转向/看向当前玩家；聚焦时长 500-700ms。
- `hold`：保持到该玩家行动结束或超时。
- `returnNeutral`：800ms 缓慢回中，避免突然甩镜。
- 新玩家接替时直接从上一位平滑过渡到下一位，不经过大幅回中。

### 6.2 镜头幅度

- 水平旋转最大 **±8°**；多人桌默认 **±4-6°**。
- 垂直俯仰最大 **±3°**。
- 不改变相机距离，不做大幅推拉。
- 相邻座位优先用「看向」而不是「绕到身后」。
- 超出安全范围时用 **视线目标偏移** 代替真实绕转。
- 玩家手动拖拽时暂停自动聚焦；松手2秒后回归焦点。
- 连续快速操作时用最短路径插值，禁止 360° 绕圈。
- 真机验收必须确认「不晕、不甩、不遮挡公共牌」。

### 6.3 聚光灯

- 当前操作玩家头顶/胸前柔和轮廓光，暖金色，强度低。
- 玩家名浮动卡片：`名字 · 剩余筹码 · 本手已下注 · 思考中`。
- 聚光不改变桌面亮度，不闪烁；可呼吸 1.2s 周期，幅度≤10%。
- 当前操作玩家 id 同时驱动 3D 名牌和 HUD 顶部提示。

### 6.4 自己回合

- 轮到本人时：
  - 聚光落在本人；
  - 显示自己的筹码、底牌、底池、可行动作；
  - 操作按钮、倒计时、快捷键提示出现；
  - 其他玩家暗化但仍可读。
- 自己回合结束后：
  - 操作栏隐藏；
  - 自己的底牌保留但降低视觉权重；
  - 焦点转移给下一位。

## 7. P0：中英术语语音

### 7.1 术语表

| 动作 | 中文 | 英文 |
|---|---|---|
| 弃牌 | 弃牌 | fold |
| 过牌 | 过牌 | check |
| 跟注 | 跟注 | call |
| 下注 | 下注 | bet |
| 加注 | 加注 | raise |
| 全下 | 全下 | all in |
| 小盲 | 小盲 | small blind |
| 大盲 | 大盲 | big blind |
| 翻牌 | 翻牌 | flop |
| 转牌 | 转牌 | turn |
| 河牌 | 河牌 | river |
| 摊牌 | 摊牌 | showdown |

### 7.2 播报规则

- 随机选择中文或英文，比例约 50/50。
- 连续两次不重复同一种语言形式。
- 金额/名字保持中文播报，术语部分中英随机。
- 例：
  - `张三 all in 200`
  - `李四 过牌 check`
  - `王五 加注 raise 到 40`
- 字幕始终显示中英双术语：`ALL IN 全下`、`CHECK 过牌`。
- 语音队列串行，不重叠；动作快速连续时合并或跳过过时播报。
- 英文语音资源与现有中文女声保持相近音量和语速。

### 7.3 资源

- 新增英文术语音频文件，按现有外部 voice 资源方式加载；
- 中文音频沿用现有资源；
- 缓存首包 + 懒加载；
- 缺失英文资源时回退中文，不阻断牌局。

## 8. P1：语音网络优化

### 8.1 问题

- raw PCM16 16kHz 每路约 256kbps；
- 4 路同时开麦，relay 需要复制转发，网络占用成倍增长；
- 没有 VAD/DTX，静音也持续发包；
- 没有自适应码率/丢包恢复。

### 8.2 目标

| 指标 | 目标 |
|---|---|
| 单路语音码率 | 16-24kbps |
| 4 人同时说话，单客户端下行 | ≤120kbps |
| 端到端延迟 | ≤200ms（4G/Wi-Fi） |
| 静音发包 | VAD 后接近 0 |
| 丢包 2% | 可懂，无明显断音 |
| 4 人开麦 10 分钟 | 不断线、不卡顿、不触发重连 |

### 8.3 方案

1. 采集端改为 AudioWorklet，替换 `ScriptProcessor`。
2. 编码改为 Opus：
   - 16kHz 或 48kHz 输入下采样；
   - 20ms 帧；
   - 16-24kbps；
   - DTX + VAD。
3. WebSocket relay 改为 Opus 包转发，保留现有二进制帧协议版本位。
4. 每个包带序号/时间戳，接收端做 jitter buffer 和丢包隐藏。
5. 服务端限制：
   - 单房间最多 4 路同时说话；
   - 单路上限 32kbps；
   - 转发缓冲上限；
   - 超限丢弃最旧音频包，不阻塞状态 SSE。
6. 前端自适应：
   - RTT/丢包升高时降码率；
   - 麦克风静音时完全停发；
   - 网络恢复后 1 秒内恢复。
7. 监听端只解码当前房间内未静音玩家。
8. 回退：Opus 不可用时保留低码率 PCM 回退，但默认关闭，需在测试环境验证。

### 8.4 与牌局连接隔离

- 音频 WebSocket 与牌局 SSE 分开；
- 音频拥塞不得阻塞 SSE/操作请求；
- 音频重连不触发牌局离线；
- 语音断线提示独立于「牌局断开」。

## 9. P1：后台连续在线

### 9.1 目标

- App 切后台 3 秒、10 秒、60 秒回到前台：
  - 不显示「已断开」；
  - 座位保留；
  - 在线状态保持；
  - 回前台 2 秒内恢复 SSE 和画面；
  - 若轮到自己操作，动作条恢复。
- 只有用户主动退出/关闭房间/超过宽限才离线。

### 9.2 方案

1. 服务端 SSE 断开不立即 `online=false`，增加 **后台宽限**：
   - 初次断开进入 `offlineGrace`；
   - 90 秒内重连恢复 online；
   - 超过宽限才清理座位/广播离线。
2. 客户端 `visibilitychange`：
   - hidden 不主动关闭 SSE；
   - 记录 hidden 时间；
   - visible 时立即检查连接、重连、拉取快照。
3. Android 端：
   - 使用前台服务/保活策略维持 WebView 网络（需平台支持评估）；
   - 若系统限制，至少保证回到前台2秒内重连。
4. 断线提示：
   - <5 秒不提示；
   - 5-90 秒显示「正在恢复连接」；
   - >90 秒显示离线。
5. 牌局公平：
   - 后台不暂停公共牌局；
   - 若后台期间轮到自己，行动倒计时仍按服务端规则；
   - 提供「回到牌桌」恢复提示，不自动代打。
6. 语音：
   - 后台默认静音上行或降到最低；
   - 回前台恢复麦克风，不重新申请权限。

### 9.3 边界

- 用户手动杀进程/关闭 App 不保证保留；
- 操作系统回收 WebView 后只能走重连；
- 90 秒宽限是服务端在线状态，不等于无限后台运行。

## 10. P1：观战自由视角

### 10.1 触发

- 玩家筹码归零且本手结束；
- 主动选择「继续观战」；
- 房间配置 loserSpectate；
- 匹配房被淘汰后仍可留房观战（若房间未关闭）。

### 10.2 能力

- 围绕牌桌 360° 水平旋转；
- 上下俯仰限制在桌面以上，不能穿模到桌下；
- 缩放范围 0.8x-1.6x；
- 单指拖动旋转，双指缩放；
- 「回到主视角」按钮；
- 自动聚焦当前操作玩家，但允许用户自由拖动打断；
- 观战状态显示「观战中 · 无操作权限」。

### 10.3 隐私

- 观战者永远不能看到任何玩家底牌；
- 服务端 `spectatorState` 继续清空 `hole/bestCards/score/handDetail`；
- 结算阶段观战者也不能看未公开底牌；
- 只能看公共牌、底池、筹码、下注、动作、赢家名字；
- 自由镜头不能通过穿模/近距离看到牌背内容（牌背无信息）；
- 观战者不能发送操作/语音默认关闭，可听不说。

### 10.4 交互

```text
[观战中]  [回到主视角]  [语音收听]
       拖动旋转 · 双指缩放
```

## 11. 数据结构与接口变更

### 11.1 结算

- `settlement.showdown`
- `settlement.totalChips`
- `settlement.contenders[].stack`
- 非摊牌时不返回 hole/bestCards/handName。

### 11.2 玩家状态

- `seats[].stack` 已有；
- `seats[].bet/committed` 需要确认在快照中暴露；
- `turn` 已有；
- 新增 `turnDeadline` 用于 HUD 倒计时。

### 11.3 语音

- WebSocket 二进制协议版本从 `PCV1` 升级到 `PCV2`；
- 头部包含版本、from、seq、codec、flags；
- 保留 V1 回退解析。

### 11.4 在线状态

- `room.players[token].online` 增加 grace 语义；
- 服务端定时器处理宽限过期；
- 不改用户账户在线统计口径。

## 12. 性能预算

| 项目 | 预算 |
|---|---|
| 语音单路 | 16-24kbps |
| 4 路语音下行 | ≤120kbps |
| 聚光灯 | 不新增实时阴影，只加低成本 Sprite/材质 |
| 镜头动画 | 500-800ms，单轴最大8° |
| 背景恢复 | 2秒内恢复首帧 |
| 结算延迟 | 15秒后弹确认 |

## 13. 分阶段计划

### Phase 1（P0，建议先做）

- 全弃牌结算隐私；
- 筹码/下注/底池显示；
- 操作玩家聚光灯与轻量镜头聚焦；
- 自己回合/他人回合状态；
- 中英术语语音。

### Phase 2（P1）

- Opus 语音 + VAD；
- 4 人开麦压测；
- 后台在线宽限；
- 观战自由视角。

### Phase 3

- 操作历史/牌局回放（本轮只保留设计，不排开发）。

## 14. 验收与发布门禁

- 开发完成 → 测试报告 → 验收报告；
- 所有 P0 AC 必须通过；
- P1 关键指标必须达标（语音、后台、观战隐私）；
- 真机测试通过才允许发布；
- 未通过则只保留测试包，不升级生产；
- 发布前备份、发布后回滚预案必须记录。
