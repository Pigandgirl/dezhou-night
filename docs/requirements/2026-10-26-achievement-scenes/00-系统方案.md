# 1000 称号与五场景系统方案

> 状态：已修复并部署 1.1.1（验收见 03/04）  
> 日期：2026-10-26  
> 当前线上：1.0.103  
> 本轮先出需求、验收和实施方案；未开发、未部署。

## 1. 目标

把当前 30 个称号扩展为至少 **1000 个可独立解锁的称号**，并新增 5 个在线匹配场景。

核心原则：

1. 称号必须有文化梗、游戏梗、电影梗、生活梗，不堆无意义数字。
2. 星级不是前置链：1-5 星按各自条件独立解锁，不存在必须先拿 1 星才能拿 5 星。
3. 约一半称号只能在在线匹配中解锁，强化参与感。
4. 5 星称号全房间播报，并给在场玩家发参与奖励。
5. 场景必须与服装、灯光、环境音、背景音乐一起变化，不能只换背景色。
6. 在线匹配随机场景；管理员可以在单机模式选择场景做测试。
7. 筹码记录来源全部中文，不显示 `friend_win`、`lobby_stay` 等英文。

## 2. 称号数据模型

```text
achievement = {
  id,                 // 唯一
  title,              // 称号名
  category,           // 三国/西游/红楼/水浒/世界史/游戏/电影/汽车/生活/牌局...
  star,               // 1-5
  scope,              // any | friend | online
  desc,               // 条件描述
  condition,          // 可执行条件
  rewardChips,        // 10/20/50/100/1000
  quote,              // 解锁文案
  secret,             // 是否隐藏条件
  scene,              // 可选：指定场景
}
```

称号数量目标：

```text
总计 1000+
一星 300 个
二星 280 个
三星 220 个
四星 140 个
五星 60 个
在线匹配限定 ≥ 500 个
```

星级和条件独立；用户可以第一局就拿到五星，也可以一直拿一星。

## 3. 1000 个称号的内容来源

不把 1000 条硬编码成 1000 段重复文本，而是采用「主题库 + 条件模板 + 人工审核」生成。

### 3.1 主题库

- 中华五千年：
  - 先秦、秦汉、三国、魏晋、唐宋、明清、近代；
  - 神话、成语、诗词、书画、戏曲、民俗、饮食、器物。
- 四大名著：
  - 三国、西游、红楼、水浒。
- 世界历史与神话：
  - 古埃及、希腊、罗马、北欧、日本战国、世界发明史。
- 游戏与流行文化：
  - 街机、主机、PC、卡牌、MOBA、桌游、网络梗。
- 电影与类型片：
  - 赛车、劫案、太空、武侠、黑色电影、公路片。
- 汽车与机械：
  - 赛车、漂移、改装、公交车、飞机、游艇、蒸汽机。
- 生活与日常：
  - 夜班、外卖、通勤、考试、加班、厨房、旅行。
- 扑克专属：
  - 手牌、下注、诈唬、摊牌、河牌、位置。

### 3.2 生成策略

1. 先建立 **300 个核心主题**（每个主题有文化典故和条件方向）。
2. 每个主题生成 2-4 个变体：
   - 首次/累计/连续/场景限定；
   - 在线/好友房/倍率/底池/牌型。
3. 对标题做人工可读性筛选：
   - 同主题不出现明显重复；
   - 不出现低俗、性暗示、侮辱性名称；
   - 不用商业游戏受版权保护的原文；
   - 避免“鸡鸡小子”这类不适合正式产品的词。
4. 生成 `achievements.json`，锁定 1000+ 条。
5. 服务端与客户端共享同一份 ID、星级、奖励和条件配置，避免不一致。

### 3.3 命名示例

- 三国：桃园结义、三英战吕布、七擒孟获、空城计、草船借箭、单骑救主、舌战群儒、刮骨疗毒、五丈原、借东风。
- 西游：大闹天宫、三打白骨精、九九八十一难、取得真经、流沙河、火焰山、真假美猴王。
- 红楼：木石前盟、大观园、金陵十二钗、海棠诗社、葬花、太虚幻境。
- 水浒：梁山聚义、一百单八将、替天行道、景阳冈、智取生辰纲。
- 世界史：斯巴达三百、亚历山大、罗马不是一天建成、特洛伊木马、埃及金字塔。
- 电影/类型：头文字、秋名山、速度与激情、盗梦、星际、黑客帝国（仅标题意象，不使用原版素材）。
- 汽车：秋名山、漂移、涡轮、老司机、夜班公交、头文字牌。
- 生活：打工人、夜班之神、外卖侠、末班车、加班冠军。
- 场景：游艇船王、草原牧羊人、万米高空、公交老司机、夜市大亨。

## 4. 星级与奖励

| 星级 | 解锁奖励 | 解锁表现 |
|---|---|---|
| 1★ | +10 大厅筹码 | 小卡片 + 轻音效 |
| 2★ | +20 大厅筹码 | 卡片 + 中等光效 |
| 3★ | +50 大厅筹码 | 金色称号卡 + 专属音效 |
| 4★ | +100 大厅筹码 | 全屏光扫 + 称号播报 |
| 5★ | +1000 大厅筹码 | 全房间播报 + 全场 +100 筹码 |

> 用户原话“一星10积分、10筹码”，由于积分已移除，方案改为 **1★+10筹码**。不恢复积分。

### 4.1 五星全房间

- 触发：在线匹配或好友房结算解锁 5★称号。
- 播报：房间内所有在线玩家/观战者收到全屏荣耀播报。
- 奖励：
  - 解锁者 +1000 筹码；
  - 房间内所有在场玩家 +100 筹码；
  - 每人每个 5★称号只发一次，幂等；
  - 机器人不发；
  - 离线者回房后不补发（或另行确认）。
- 现场文案：

```text
荣耀时刻
玩家 X 解锁五星称号「游艇船王」
全房间同庆，所有在场玩家获得 100 大厅筹码
```

## 5. 条件与生涯指标

为了让 1000 个称号可以交叉激活，生涯记录需要扩充：

```text
hands, wins, ties, losses
friendHands, friendWins
onlineHands, onlineWins
foldWins, showdownWins
allInWins, comebackWins
biggestPot, highestChips
currentStreak, bestStreak
handTypeWins[10]
sceneWins[6]
totalChipsEarned, totalChipsSpent
raises, calls, checks, folds
onlineOnlyWins
companions count, max intimacy
differentDaysPlayed
consecutiveDays
titlesUnlocked, fiveStarUnlocked
timePlayedMinutes
```

可组合条件：

- 累计手数、胜场、底池、连胜；
- 某牌型获胜 N 次；
- 某场景获胜 N 次；
- 在线匹配专属；
- 与同一好友/不同好友；
- 夜场/通宵/连续天数；
- 全下/翻盘/诈唬；
- 场景+服装+牌型交叉；
- 生涯总筹码/历史最高。

## 6. 五个新场景

现有场景保留为：

```text
private  昏暗私人牌室（默认，当前风格）
```

新增 5 个：

| ID | 场景 | 服装 | 灯光 | 环境音 | 音乐 |
|---|---|---|---|---|---|
| yacht | 海上游艇 | 夏威夷衬衫/度假装 | 夕阳暖光、海面反射 | 海浪、海鸥、船体轻响 | 慵懒爵士/Bossa |
| bus | 夜班公交 | 各行业工装 | 车厢冷白灯+城市霓虹 | 发动机、报站、雨刷、街道 | 城市 Funk |
| grassland | 草原牧场 | 牧羊服/毡帽 | 日光、蓝天、暖风 | 风、羊叫、远处鸟鸣 | 木吉他/民谣 |
| airplane | 万米高空 | 西装/制服 | 客舱暖光、舷窗云层 | 发动机、安全带提示、广播 | 轻爵士 |
| night_market | 霓虹夜市 | 复古花衬衫/围裙 | 红灯笼+霓虹 | 人声、锅气、远处叫卖 | 中式复古爵士 |

### 6.1 场景表现

每个场景必须有：

- 独立背景/环境几何；
- 独立灯光色温与光源强度；
- 牌桌/椅背/名牌的材质色调；
- 玩家服装配色/外套；
- 环境音循环；
- 背景音乐和弦/节奏；
- 场景名与氛围标签；
- 手机性能降级版本（低画质关闭粒子/远景模型）。

### 6.2 场景进入规则

- 在线匹配：创建/开局时服务端随机分配场景，整个房间同步；同一局不中途换场。
- 好友房：默认 private（本轮不做随机），后续可扩展。
- 单机：
  - 普通玩家默认 private；
  - admin 账号在大厅显示场景选择器，可强制选择 6 个场景之一做测试；
  - 选择只影响单机测试，不写入在线房间。
- 连续匹配多次应能出现不同场景；避免连续重复同一场景。

### 6.3 音乐与音效

- 每个场景独立曲风；
- 切换场景时 0.8-1.5s 交叉淡出/淡入；
- 环境音循环不能有爆音/断点；
- 音乐/环境音音量受设置控制；
- 关闭音乐时保留环境音（可配置）；
- 不引用商业电影/游戏原声。

## 8. 实现分阶段

### Phase A：称号数据与奖励

- 生成 1000+ 条数据；
- 服务端条件引擎、幂等解锁、星级奖励；
- 五星房间广播/全员100；
- 中文来源；
- 生涯指标扩充。

### Phase B：场景基础

- 5 个场景切换、服装、灯光、环境音、音乐；
- 在线随机、房内同步；
- admin 单机选择。

### Phase C：真实游玩验收

- 单机逐场景检查；
- 在线匹配随机场景；
- 1000 称号计数、星级奖励、五星广播；
- 截图/录屏/抓包。

## 9. 风险

- 1000 条内容生成容易重复/低质，必须审核；
- 5★ 全房间奖励可能被刷，需要幂等与每日限制；
- 1000 条数据增加包体，需压缩和懒加载；
- 5 个场景会显著增加 3D/音频资源，需性能预算；
- 在线随机场景需要服务端同步；
- 音乐/环境音版权必须自制/授权；
- 场景服装/光影改动大，需分阶段验收。
