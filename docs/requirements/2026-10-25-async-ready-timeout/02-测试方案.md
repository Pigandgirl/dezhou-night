# 异步准备与倒计时修复测试方案

## 范围与不在范围

### 范围内

- 候选集合只统计在线活跃玩家；
- 离线/离开玩家不阻塞；
- 5 人局变 4 人；
- 5 人游戏中第 6 人等待下一手；
- 下一手玩家列表排除离线；
- 15 秒常量；
- 全部准备立即开始；
- 结算 UI 倒计时文本；
- 初始在线匹配就绪过滤；
- Android 构建。

### 不在范围

- 真实多人并发压力测试；
- 真实手机断网重连；
- 牌局发牌/结算算法；
- 好友房房主手动开局的权限变更。

## 测试策略

- **GameEngine 单元测试**：构造房间、当前手牌、在线/离线/等待玩家，断言候选、准备数、`checkNextReady`、`nextHand` 玩家列表。
- **UI 测试**：Playwright 强制打开结算层，调用 `setOnlineNextState` 和 `setOnlineNextTimer`，检查文本。
- **构建**：build-apk.ps1。
- **初始匹配**：代码审查 + 单元候选过滤；无真机多账号压力。

## 环境

- Node 26；
- GameEngine 直接 require；
- Edge Playwright；
- 1.0.89 / versionCode 90；
- 无真机。

## 用例表

| 编号 | 对应需求 | 前置 | 步骤 | 预期 |
|---|---|---|---|---|
| T1 | R1,R2 | 5 人房，其中1人退出 | 检查候选 | 只有4人 |
| T2 | R3 | 4活跃全部准备 | checkNextReady | started=true |
| T3 | R2 | 当前手有一人offline | 候选 | 不包含offline |
| T4 | R6 | 5人在玩，第6人waitingNext | 候选/准备数 | 6人，ready6 |
| T5 | R7 | 等待玩家下一手 | 调用nextHand | 玩家包含6，不包含offline |
| T6 | R4,AC5 | 读取常量 | NEXT_HAND_MS | 15000 |
| T7 | R9 | 结算UI | set counts/timer | `已准备 2/4 · 下一手 15s` |
| T8 | AC9 | 构建 | APK | 1.0.89成功 |

## 命令清单

```powershell
node --check server/lib/game-engine.js
node --check server/server.js
node --check src/online-3d.js
node --check src/hud.js
powershell -ExecutionPolicy Bypass -File .\scripts\build-apk.ps1
```

## 风险与降级

- 若15秒自动开局引发AFK问题，可调大倒计时或改为主动准备；
- 中途加入自动准备是明确产品规则，不另行提供取消按钮；
- 真机SSE断开时服务端会立即从候选剔除，重连后重新加入。
