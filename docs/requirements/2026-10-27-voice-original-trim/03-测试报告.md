# 原速播报与称呼/操作无缝衔接测试报告

> 版本：1.1.11（versionCode 117）  
> 日期：2026-10-27  
> 环境：Edge/Playwright，单机 AI 对战  
> 无真机扬声器听感

## 1. 修复

- 删除队列速率分级，`speechRateForQueue()` 固定返回1；
- `playBuffer()` 强制 `playbackRate.value = 1`；
- 不再对正在播放的音频做实时加速；
- 新增 `trimSpeechBuffer()`：按0.006幅度阈值裁掉首尾静音，保留15ms/45ms缓冲；
- 称呼播放完成立即进入操作音频，中间无 `setTimeout` / 等待。

## 2. 单机 AI 实测

完整数据：`evidence/ai-voice-gap.json`

样本：

```text
阿凯 名称
  rate = 1
  rawDuration = 1.368s
  trimStart = 0.196s
  played = 0.578s
  end = 7942ms

操作 en_call,en_two
  start = 7942ms
  end = 8793ms

名称结束 → 操作开始 = 0ms
```

后续动作：

```text
阿凯名称 → en_call,en_two 立即开始
AI 下一手名称 → 对应操作立即开始
pageerror = 0
```

名称+跟注总时长约：

```text
0.578 + 0.851 ≈ 1.43s
```

## 3. 原速确认

日志中所有 `rate` 均为 **1**，不再出现 1.8/2.1/2.3/2.5。

## 4. 静音裁剪

“阿凯”原始音频1.368s，实际称呼语音约0.578s，剩余约0.6s为尾部静音；裁剪后操作立即开始。
同时裁掉约0.196s开头静音，使称呼更快进入。

## 6. 未覆盖/风险

- 真机扬声器听感未验证；
- 静音裁剪阈值对个别短音可能略紧，但保留了45ms尾部缓冲；
- 当前是原速，极端连续操作仍可能排队，但不再人为打断；
- 服务端 TTS 首次生成仍有网络耗时。
