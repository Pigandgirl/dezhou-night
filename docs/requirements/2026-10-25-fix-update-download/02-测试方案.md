# 修复更新下载失败测试方案

## 范围与不在范围

### 范围内

- WebView fetch 下载 APK；
- 64KB 分片传输；
- 进度显示；
- 失败状态与浏览器下载入口；
- Android 编译；
- 生产版本清单和 APK 可达性。

### 不在范围

- 真实手机系统安装器点击；
- 不同厂商 ROM 的未知来源权限页面；
- 弱网/断点续传压力测试；
- 旧版 1.0.82 通过自身旧下载器自动升级（其代码无法用新逻辑修复）。

## 测试策略

- **接口/集成**：本地启动游戏服务，页面通过同源 `/download/*.apk` 取 APK。
- **前端逻辑**：注入 mock `NativeBridge`，验证 begin/append/finish 调用、字节数、分片数。
- **错误 UI**：调用 `setUpdateProgress(-1)` 验证失败、重试和浏览器入口。
- **构建**：执行仓库 `scripts/build-apk.ps1` 全量构建。
- **生产验证**：`curl` 检查 latest JSON 与 APK HTTP 状态。
- 不伪造真机安装结果。

## 环境与数据

- Windows、PowerShell、Node 26、Python 3；
- Chromium/Edge via Playwright；
- 本地 QA 沙箱服务；
- 生产地址 `http://192.144.159.220:8080`；
- 测试 APK：`server/public/apk/DezhouNight-1.0.83.apk`（1,275,797 字节）。

| 编号 | 对应需求 | 前置条件 | 步骤 | 预期结果 |

## 将要执行的命令清单

```powershell
node --check src/hud.js
powershell -ExecutionPolicy Bypass -File .\scripts\build-apk.ps1
curl.exe -s http://192.144.159.220:8080/api/app/latest
curl.exe -sI http://192.144.159.220:8080/download/DezhouNight-1.0.85.apk
```

Playwright 集成测试入口：本地启动 QA 沙箱，注入 mock NativeBridge，调用 `__poker.hud.downloadApkInWebView()`，记录 `size/total/chunks/finished/progress`。

## 风险与降级

- 如果 WebView fetch 被跨域或混合内容策略拦截，保留 Android DownloadManager → HttpURLConnection → 浏览器下载三层降级；
- 如果 JS Bridge 写入失败，调用 `abortWebUpdate` 清理半包；
- 如果真实设备安装失败，用户仍可用浏览器手动下载 APK。
