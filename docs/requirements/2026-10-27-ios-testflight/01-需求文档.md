## 1. 背景与目标

用户要求用 **TestFlight** 分发 iOS App：

- 开发者账号上传构建；
- 测试者安装 TestFlight App，接受邀请后安装；
- 每个构建 90 天有效；
- 需要保留网页版的语音/麦克风能力。

现有 iOS 工程是 `WKWebView` 壳，加载与 Android/网页相同的 `/play`。
之前只做过无签名 IPA 和模拟器构建；本次要把它做成 **可签名上传 TestFlight** 的工程，
并接好上传流水线。

## 2. 编号需求

| 编号 | 需求 |
| --- | --- |
| R1 | iOS 工程可编译出 App Store 可用的 archive（含 AppIcon、PrivacyInfo、麦克风用途说明） |
| R2 | 提供 TestFlight 上传工作流：签名 archive → 导出 `app-store-connect` IPA → 上传 App Store Connect |
| R3 | 测试者通过 TestFlight 安装；构建 90 天有效，过期后重新上传 |
| R4 | 使用稳定 HTTPS URL，保证 WKWebView 内 `getUserMedia`（房间语音）可用 |
| R5 | App 中文名/界面文案正确，Bundle ID 与 App Store Connect 一致 |
| R6 | 签名材料/API Key 只放 GitHub Secrets，不进入仓库 |
| R7 | 说明内部测试（无需 Beta App Review）与外部测试（需要审核）的差别 |
| R8 | 提供可复现的测试命令与证据，不把“未上传”说成“已发布” |

## 3. 用户场景

1. 开发者（有付费 Apple Developer Program）在 App Store Connect 建 App 记录；
2. 把 Distribution 证书、App Store profile、App Store Connect API Key 放进 GitHub Secrets；
3. 运行 `iOS TestFlight Upload`，输入稳定 HTTPS 的 `app_url`；
4. App Store Connect 处理构建；
5. 测试者安装 TestFlight，接受内部/外部邀请，安装「德扑之夜」；
6. 90 天内测试；过期前重新上传构建。

## 4. 边界与非目标

**在范围：**

- iOS WKWebView 壳、麦克风权限、中文文案、PrivacyInfo；
- GitHub Actions 签名/上传工作流；
- TestFlight 内测/外测流程说明。

**非目标：**

- 不保证外部 TestFlight 一定通过 Beta App Review（WebView 壳有 4.2 风险）；
- 不替代 App Store 正式上架审核；
- 不改造游戏为纯原生；
- 不创建 Apple 开发者账号、不代付 $99/年；
- 不把 HTTP 生产地址当成稳定 TestFlight 后端。

## 7. 风险

- **4.2 Minimum Functionality**：纯 WebView 壳在外部 TestFlight Beta Review/上架时可能被拒；
  内部测试（App Store Connect 用户）不经过 Beta App Review。
- **HTTPS**：TestFlight 工作流拒绝 `http://`；没有稳定 HTTPS 时不能保证语音。
- **ATS**：调试构建保留 `NSAllowsArbitraryLoads`；TestFlight 工作流会自动删除该例外，
  要求页面所有资源都走 HTTPS。
- **90 天**：构建到期后测试者无法继续安装；需重新上传，不是永久分发。
- **App Review**：扑克/模拟赌博内容需如实填写年龄分级，外部测试需 Beta App Review。
- **构建号**：每次上传必须使用更大的 `CFBundleVersion`；工作流默认用时间戳。
