## 3. 上线前必须补齐

1. **付费 Apple Developer Program** 的 Team ID；
2. App Store Connect 创建 App 记录（Bundle ID `com.dezhounight.poker`，名称/SKU/语言）；
3. Distribution Certificate + App Store Provisioning Profile
   （或确认可用的自动签名方案）；
4. App Store Connect API Key（Key ID、Issuer ID、`.p8`）；
5. 稳定 HTTPS `app_url`（必须是 `https://`，且页面/接口全部 HTTPS）；
6. 测试者名单与内部/外部测试策略。

## 4. 发布建议

- **先做内部 TestFlight**：内部测试不需要 Beta App Review，适合验证安装/启动/基本玩法；
- **外部 TestFlight** 需要 Beta App Review；纯 WebView 壳有 4.2 最低功能风险，
  若被拒，需要补原生能力或改为内部测试；
- 首次上传前确认 **Build number** 唯一且递增；构建 90 天后过期，需重新上传；
- TestFlight 版必须使用 HTTPS，否则房间语音不可用；HTTP 只适合无语音调试；
- 上传前把网页端的底池/其他修复先发布到同一个 HTTPS 站点，否则 App 只是壳，
  仍会打开旧网页。

## 5. 阻塞原因（具体）

- 没有 Team ID、Distribution 证书、App Store profile、App Store Connect API Key；
- 没有稳定的 HTTPS 域名/证书；
- 没有在 App Store Connect 创建 App 记录；
- 因此无法执行 `xcodebuild archive` 的签名步骤，也无法运行 `altool` 上传。

## 6. 结论

iOS App 的**代码和 CI 上传流水线已经准备好**，无签名构建和模拟器启动已通过；
但 TestFlight 是 Apple 账号侧的分发动作，当前缺少账号材料与 HTTPS 入口，
**不能声称已经上传或可供测试者安装**。补齐第 3 节材料后，运行
`iOS TestFlight Upload` 即可完成签名、上传和 TestFlight 分发。
