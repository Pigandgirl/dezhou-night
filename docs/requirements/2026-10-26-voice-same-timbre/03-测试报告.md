# 称呼与动作统一音色测试报告

> 版本：1.1.5（versionCode 111）  
> 日期：2026-10-26  
> 环境：Edge/Playwright；本地与生产；无 Android 真机听感

## 1. 根因

1.1.4：

- 称呼走系统 TTS；
- 动作走离线音色包；
- 两个引擎，两个音色。

## 2. 修复

- 服务端新增 `/api/voice/name`；
- 使用与音色包相同基础发音人生成称呼音频；
- 8 profile 固定基础发音人/rate/pitch；
- profile+name 缓存；
- 客户端预取称呼；
- 先播称呼音频，结束后播同 profile 动作包；
- 正常路径不调用系统 TTS。

## 3. 服务端实测

生产：

```text
GET /api/voice/name?profile=male_deep&name=阿凯
first = 200, 7344 bytes, 2.30s
cached = 200, 0.08s
```

## 4. 客户端实测

本地/生产：

```text
loadNameAudio('阿凯') duration = 1.224s
speak('raise',150,'阿凯')
profile = male_deep
TTS调用 = 0
动作键 = ['en_raise','en_one','en_hundred','en_fifty']
pageerror = 0
```

称呼和动作都来自 `male_deep` 的基础发音人，不再混用系统 TTS。

## 7. 未覆盖/风险

- 服务端 TTS 首次生成约2-5秒，已通过预取/缓存降低影响；
- 服务器/TTS网络不可用时回退系统 TTS，会出现两个音色；
- 真机主观听感未验收；
- 名称是用户输入，已限制12字并去除SSML特殊字符。

## 8. 结论

正常路径下称呼与动作使用同一基础发音人，TTS调用为0；生产接口200，缓存命中。真机听感仍待确认。
