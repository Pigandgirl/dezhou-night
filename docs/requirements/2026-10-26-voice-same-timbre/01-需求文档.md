# 称呼与动作统一音色需求文档

> 状态：已实现并部署 1.1.5  
> 日期：2026-10-26

## 背景

1.1.4 用系统 TTS 读玩家称呼、用离线音色包读动作，导致同一句播报出现两个不同音色：

```text
[系统TTS] 阿凯
[离线音色包] 加注 150
```

## 目标

- 称呼和操作使用同一个音色；
- 该音色就是用户在设置里选择的音色；
- 中文/英文都统一；
- 保留玩家称呼；
- 系统 TTS 只作为服务器不可用时的兜底。

## 方案

- 服务端新增 `/api/voice/name`：用与音色包相同的 Edge 基础发音人生成称呼音频；
- 8 个音色各自有固定基础发音人/音高/语速；
- 生成结果缓存，客户端预取；
- 客户端先播放服务端称呼音频，结束后再播放同 profile 的动作音色包；
- 中文/英文称呼和动作都来自同一基础发音人；
- 正常路径完全不调用系统 TTS；
- 服务端不可用时才回退 TTS。

## 需求

- **R1** 称呼音频使用所选 profile 的基础发音人。
- **R2** 动作音频使用同一 profile 的音色包。
- **R3** 称呼播完后再播动作，不叠音。
- **R4** 称呼与动作音色一致。
- **R5** 服务端按 profile+name 缓存称呼音频。
- **R6** 客户端预取同房间玩家称呼。
- **R7** 首次生成失败时回退 TTS。
- **R8** 中文/英文动作继续随机。
- **R9** 不改变牌局/成就/筹码。
- **R10** 名称为空/超长安全处理。

## 验收

- **AC1** `/api/voice/name` 返回所选 profile 音频。
- **AC2** 同一称呼再次请求命中缓存。
- **AC3** 客户端称呼音频播放后动作键才出现。
- **AC4** 正常路径 TTS 调用次数为0。
- **AC5** 称呼和动作使用同一个 profile。
- **AC6** 页面无JS错误。
- **AC7** APK/生产1.1.5。
