# 语音卡顿优化测试方案

## 范围与不在范围

### 范围内

- WebSocket 二进制 PCM 传输；
- 20ms 分帧；
- `pid + seq` 帧头；
- 自适应 jitter buffer；
- HTTP+SSE 兜底队列；
- 老 HTTP 发送端与 WS 接收端互通；
- 原有禁音/只听/全部静音回归；
- Android 构建。

### 不在范围

- Opus 编码质量；
- 真实手机扬声器听感；
- 弱网 10% 丢包压力测试；
- 蓝牙耳机路由；
- AudioWorklet 环形缓冲。

## 测试策略

- **端到端 WS**：两个 Playwright 页面同房；A 开麦，B 不开麦；统计发送/接收包数和 jitterTarget。
- **HTTP 兜底**：页面启动前 `window.WebSocket=undefined`，重复上述流程；确认 30 帧全部到达且 `httpQueue` 清空。
- **兼容性**：HTTP 音频端点现在同时向 WS 中继转发；WS 音频同时广播 SSE。
- **回归**：禁音/只听/全部静音断言。
- **构建**：build-apk.ps1。
- **听感**：当前环境无法人工听，真机作为阻塞项。

## 环境与数据

- Windows / Edge Chromium / Playwright；
- Chromium fake microphone；
- 本地 QA 服务；
- 1.0.87 客户端，versionCode 88；
- APK 1,283,989 字节。

## 命令清单

```powershell
node --check src/voice.js
node --check server/server.js
powershell -ExecutionPolicy Bypass -File .\scripts\build-apk.ps1
curl.exe -s http://192.144.159.220:8080/api/app/latest
```

端到端断言：

```js
wsActive === true
packetsSent === 145
packetsReceived === 145
jitterTarget >= 0.32
audioContext.state === 'running'
```

## 风险与降级

- WS 混合内容被拦截：HTTP 完整队列兜底；
- WS 断开：自动重连，期间 SSE 继续播放；
- 缓冲过大：最大 550ms，超过 1.4 秒直接重置；
- 真机听感不达标：下一步接 Opus + AudioWorklet。
