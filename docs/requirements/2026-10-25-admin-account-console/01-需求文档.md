# admin 主账号后台管理集成需求文档

## 背景与问题

当前后台管理系统位于独立 `/admin` 页面，需要再次输入管理员账号密码；游戏主账号 `admin` 登录后看不到后台入口，也无法用游戏会话直接做运营管理。

用户要求：

- `admin` 登录主页面后出现「后台管理」按钮；
- 使用同一个 admin 主账号直接进入后台，不再重复登录；
- 能实时查看服务器信息、在线游玩人数、进行中的游戏；
- 能使用原后台网页的全部管理功能；
- 能做统一权限开关管理。

## 目标

- 游戏主账号 admin 与后台管理员身份统一；
- admin 的游戏 token 直接具备后台 API 访问权限；
- 主页面显示后台入口；
- 后台页面自动识别从游戏带过去的 token；
- 概览增加在线玩家、进行中游戏、运行时间、内存、连接数；
- 后台概览/房间每5秒自动刷新；
- 普通用户无后台按钮，调用后台 API 返回401。

## 需求点

- **R1** `accountView` 增加 `isAdmin`，仅 `ADMIN_USER` 对应游戏账号为 true。
- **R2** `/api/admin/*` 除管理员 token 外，也接受 admin 游戏账号的 Bearer token。
- **R3** admin 游戏登录后在主大厅顶部显示「后台管理」按钮。
- **R4** 点击按钮打开 `${origin}/admin#token=<gameToken>`，使用 URL fragment 不把 token 发给服务器日志。
- **R5** 后台页面读取 fragment token，写入后台会话并自动进入控制台。
- **R6** 后台 URL 清空 hash，避免 token 留在地址栏。
- **R7** 后台概览新增在线玩家、观战、进行中游戏、服务器连接、运行时间、内存。
- **R8** 概览/房间每5秒自动刷新，页面隐藏时暂停请求。
- **R9** 原用户管理、对局记录、房间管理、权限开关全部保留。
- **R10** 后台增加「返回游戏」。
- **R11** 普通用户强制访问后台 API 仍为401。

## 页面设计

主大厅顶部：

```text
[ONLINE 1] [🛡 后台管理] [设置]
```

后台概览：

```text
注册用户   在线玩家   进行中游戏
服务器连接 服务器内存 累计对局

当前房间
匹配 1 号房 ...
```

后台侧栏：

```text
概览 / 用户管理 / 对局记录 / 房间 / 权限开关
刷新数据
返回游戏
退出后台
```

## 非目标

- 不嵌入游戏内 iframe；
- 不改变原后台直接 ADMIN_USER/ADMIN_PASSWORD 登录；
- 不新增管理员角色表；
- 不改变用户管理接口；
- 不在客户端暴露管理员密码。

## 验收标准

- **AC1** admin 游戏账号 API 返回 isAdmin=true。
- **AC2** admin 主页面显示后台管理按钮。
- **AC3** 普通账号不显示后台管理按钮。
- **AC4** 点击按钮生成的 URL 含 game token fragment。
- **AC5** 后台页面自动进入，不显示登录表单。
- **AC6** admin 游戏 token 调 `/api/admin/overview` 返回200。
- **AC7** 普通账号 token 调后台 API 返回401。
- **AC8** 概览展示在线玩家、进行中游戏、运行时间和内存。
- **AC9** 5秒自动刷新生效。
- **AC10** Android 1.0.94 构建通过。
- **AC11** 真实生产 admin 游戏密码未在测试中验证（密码由用户持有）。

## 风险

- 游戏 token 通过 URL fragment 传递；fragment 不发服务器，但仍在浏览器地址栏，已立即清空；
- 后台 localStorage 会缓存 token，退出后台只清后台本地 token；
- admin 游戏 token 被撤销后后台 API 401；
- 直接 `/admin` 登录仍依赖环境变量密码。
