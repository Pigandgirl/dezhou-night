# 02 测试方案：项目上传 GitHub 公开仓库

- 日期：2026-10-30
- 关联需求：`01-需求文档.md`（R1–R9、AC1–AC11）
- 测试对象：`D:\software\project\dezhou` 公开快照、`Pigandgirl/dezhou-night` 远程仓库

## 1. 范围

### 在范围

- 快照内容正确性：应上传的源码/配置/文档在列，应排除的产物/密钥不在列；
- 密钥扫描：keystore、OpenSSH 私钥、证书、`.env`；
- 体积与单文件限制：单文件 < 100 MB，仓库 ≤ 200 MB；
- 仓库创建与推送：公开可见性、默认分支、提交数；
- 远程一致性：远程树与本地 `main` 一致，`master` 未被推送；
- 可运行性：`npm run build`、`node server/server.js` 健康检查；
- 文档完整性：README 相对链接、四份过程文档；
- 匿名访问：不带凭据获取仓库页面与 raw 文件。

### 不在范围

- 游戏功能回归（单机/在线/语音/支付）——本次不改业务代码；
- GitHub Actions 的 iOS 构建是否成功（只观察，不作为阻塞项）；
- 生产部署、服务器变更、DNS/HTTPS 配置；
- APK 签名与分发验证（密钥刻意不入库）；
- GitHub 组织权限、分支保护、Issue/PR 模板。

## 5. 将要执行的命令

```powershell
# 本地快照
git ls-files
git ls-files | Measure-Object
git status --short
Get-ChildItem . -Recurse -File | Where-Object { $_.Length -gt 100MB }

# 密钥扫描
git ls-files | Select-String -Pattern 'keystore|\.pem$|\.key$|lhr_key'
Select-String -Path (git ls-files) -Pattern 'BEGIN (OPENSSH|RSA|EC) PRIVATE KEY'

# 构建
npm run build

# 服务冒烟
$env:PORT='18080'; $env:ADMIN_USER='qaadmin'; $env:ADMIN_PASSWORD='QaAdmin!2345'
node server/server.js
Invoke-WebRequest http://127.0.0.1:18080/api/health -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:18080/play -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:18080/admin -UseBasicParsing

# 远端
gh repo create Pigandgirl/dezhou-night --public --description "德扑之夜 · 第一视角德州扑克"
git remote add origin https://github.com/Pigandgirl/dezhou-night.git
git push -u origin main
gh repo view Pigandgirl/dezhou-night --json name,visibility,defaultBranchRef,url
gh api "repos/Pigandgirl/dezhou-night/git/trees/main?recursive=1" --jq '.tree[].path'
gh api repos/Pigandgirl/dezhou-night --jq '{size,default_branch,visibility}'
Invoke-WebRequest https://github.com/Pigandgirl/dezhou-night -UseBasicParsing
Invoke-WebRequest https://raw.githubusercontent.com/Pigandgirl/dezhou-night/main/README.md -UseBasicParsing
gh run list -R Pigandgirl/dezhou-night
```

## 6. 风险与降级

| 风险 | 概率 | 降级方案 |
|---|---|---|
| 100 MB 推送超时/中断 | 中 | 后台任务执行；失败后重试 `git push`；仍失败改用 SSH 或分批历史提交 |
| GitHub 拒绝大仓库 | 低 | 排除 `docs/requirements` 证据图，体积降至约 35 MB |
| 远程误含密钥 | 低 | 删除仓库重建；用 `gh api` 树复核；必要时 `git filter-repo` |
| 端口 18080 被占用 | 低 | 改用 18081/18082 |
| `npm run build` 失败 | 低 | 记录原始报错，标记 AC8 失败，检查 Node 版本与依赖 |
| Actions 构建失败 | 中 | 记录为已知问题，不影响仓库内容验收 |
| 公开生产地址带来扫描 | 中 | 在 04 中记录风险，建议尽快启用 HTTPS/域名并改密 |

## 7. 通过准则

- AC1–AC11 全部通过（Actions 仅记录，不计入）；
- 任一密钥类文件出现在远程即视为**阻断性失败**，必须立即删除仓库并重建；
- 失败项必须原样记录在 `03-测试报告.md`，不得省略。
