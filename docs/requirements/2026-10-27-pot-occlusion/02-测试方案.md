# 底池数字被公共牌遮挡 — 测试方案

- 对应需求：[01-需求文档.md](01-需求文档.md)
- 测试对象：本地构建的网页牌桌（同一份 3D 场景 + HUD）
- 测试类型：DOM/几何布局测试 + 截图目检；不做发牌/结算逻辑回归

## 1. 范围与不在范围

**在范围**：

- 横屏桌面 1440×900、用户截图比例 1200×540、手机横屏 852×393；
- 竖屏 390×844；
- `.potbox` 与 `#boardRail` 是否相交；
- 3D 底池标签是否隐藏；
- `#potValue` 是否仍显示 234；
- before/after 截图。

**不在范围**：

- 真实 Android/iOS GPU 渲染差异；
- 发牌、下注、结算正确性；
- 2D 客机牌桌 `.gt-pot`；
- 生产发布（需凭据，单独验收）。

## 2. 测试策略

| 层级 | 方法 |
| --- | --- |
| 布局 | 用 Playwright/CDP 读取 `.potbox`、`#boardRail` 的 `getBoundingClientRect()`，比较底池顶边与牌栏底边 |
| 3D | 读取 `scene.potStack.labelSprite.visible`，确认大号标签已隐藏 |
| 数值 | 调用 `hud.setPot(234)` 后读取 `#potValue` |
| 视觉 | 同一状态截图 before/after，人工确认牌面与底池文字 |
| 回归 | 公共牌、底牌面板、玩家筹码、桌面布局同屏检查 |

**测试数据**：固定底池 234，公共牌 J♠ K♥ 2♦ 4♥ 9♣（与用户截图一致）。

**环境**：Windows + Edge headless（Playwright），本地沙盒服务器；
页面按 `APP_VERSION=1.1.14`、`APP_VERSION_CODE=121` 构建，避免与最新版本
校验弹窗冲突。

## 4. 执行命令

```powershell
# 构建（测试时与生产 1.1.14 对齐，避免更新弹窗）
$env:APP_VERSION='1.1.14'
$env:APP_VERSION_CODE='121'
npm run build
Copy-Item dist\index.html server\public\web\index.html -Force

# 修复后布局测试（可直接重跑）
node qa\run-pot-layout.mjs final4
```

> 修复前的 `node qa\run-pot-layout.mjs before` 只用于留档；源码修复后重跑
> 会得到新布局，不能再复现旧截图。旧结果见
> [evidence/pot-layout-before.log](evidence/pot-layout-before.log)。

## 5. 证据要求

- 每个视口 before/after 截图；
- 原始 stdout 日志（含 `potbox`、`rail`、`spriteScreen`、`overlap`、`ok`）；
- 用户原始截图；
- 测试报告 [03-测试报告.md](03-测试报告.md) 引用上述文件。

## 6. 风险与降级

- 若某视口仍相交：优先调 `.potbox` 的 `top`，不要移动公共牌；
- 若短屏底池条碰到行动条：单独为 `max-height: 420px` 增加更小 top；
- 若自动化与真机观感不一致：以真机截图为准，保留 DOM 测量作为回归门槛。
