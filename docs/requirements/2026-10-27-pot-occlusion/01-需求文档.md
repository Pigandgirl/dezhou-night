# 底池数字被公共牌遮挡 — 需求文档

- 日期：2026-10-27
- 状态：本地已修复并验证，生产待发布
- 问题来源：用户截图（2400×1080，网页端/移动端横屏）
- 相关代码：`src/layout.js`、`src/scene.js`、`src/style.css`

## 1. 背景与问题

用户截图（[user-report.jpg](evidence/user-report.jpg)）显示：公共牌 J、K、2、4、9
显示在牌桌上方，底池数字「234」位于公共牌后方，被牌面覆盖，无法完整阅读。

原因有两层：

1. **3D 底池标签在公共牌后面**：底池筹码堆位置
   `POT_SPOT = (0, TABLE_Y+0.002, -0.235)`，公共牌位置
   `communitySpots()` 的 `z=-0.06`；底池在公共牌更远处，投影到屏幕后落在
   公共牌背后。桌面 1440×900 时投影 y≈285，尚未压到 HUD 牌栏；
   横屏 852×393 时投影 y≈125，正好落在 HUD 牌栏（126–168）内，
   被公共牌遮挡（见 [before 日志](evidence/pot-layout-before.log)）。
2. **顶部 HUD 底池条被隐藏**：`src/style.css` 末尾原本有
   `.potbox { display: none !important; }`，只剩 3D 大号数字标签；
   而该标签又落在牌后，用户没有可读的底池数字。

这是布局/视觉问题，不涉及发牌、下注或结算逻辑。

## 2. 目标与成功标准

**目标**：在网页端、移动端横屏和竖屏下，底池数字始终位于公共牌下方，
完整可见，不与公共牌文本/牌面发生遮挡；底池数值继续实时同步。

**成功标准**：

- 公共牌出现后，底池 HUD 的矩形区域与公共牌 HUD 的矩形区域不相交；
- 底池数字仍为正确的当前底池值；
- 3D 桌面中间不再出现被牌面压住的大号底池数字；
- 原有公共牌、底牌面板、玩家筹码标签不被新布局破坏。

## 3. 用户场景

- 用户在 1200×540 的网页窗口（用户截图比例）玩单机/在线牌桌，
  翻牌后看底池；
- 用户在 852×393（手机横屏）或 390×844（手机竖屏）打开牌桌；
- 用户希望底池数字像 HUD 一样可读，而不是被公共牌盖住。

## 4. 编号需求

| 编号 | 需求 |
| --- | --- |
| R1 | 底池数字使用顶部 HUD 小条（`.potbox`）展示，位于公共牌牌栏下方 |
| R2 | 隐藏 3D 筹码堆上的大号底池数字，保留筹码堆本身 |
| R3 | 横屏 HUD 底池位置随视口高度调整：桌面 300px、短横屏 208px |
| R4 | 竖屏时底池条放在顶部提示条下方（110px），不被提示条遮挡 |
| R5 | 底池值仍由 `hud.setPot()`/`#potValue` 驱动，不改游戏逻辑 |
| R6 | 不影响公共牌、底牌面板、玩家筹码、行动条等既有 HUD |

## 5. 边界与非目标

**边界**：

- 只改 HUD 与 3D 底池标签显示；不改公共牌位置、牌桌几何、相机。
- `.gt-pot`（2D 客机牌桌的底池）保持原样。
- 生产发布需要部署权限；本地修复不等同于生产已上线。

**非目标**：

- 不重做牌桌 UI，不改变底池筹码数量/面额；
- 不调整公共牌尺寸或位置；
- 不处理语音、账号、压测等其他需求。

## 7. 依赖与风险

- **依赖**：浏览器 WebGL、现有 HUD DOM、`hud.setPot`/`setBoardCards`。
- **风险 1（已发生）**：生产 1.1.14 仍是旧布局；没有 `DEPLOY_PASS`/SSH，
  本次只完成本地构建，尚未发布。
- **风险 2**：极短横屏（高度 <360px）时 208px 的底池条可能与行动条接近；
  本轮未覆盖该尺寸，建议后续单独测。
- **风险 3**：竖屏底池条会盖住荷官上半身（不是文字遮挡）；不影响数字阅读，
  但视觉上仍可继续优化。
- **风险 4**：自动化是 DOM/投影测量 + 截图，不等同于真机 GPU 观感；
  需在 Android/iOS 真机复验。
