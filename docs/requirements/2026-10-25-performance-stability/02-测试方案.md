# 系统响应与稳定性优化测试方案

## 范围

- 生产静态压缩（br/gzip）；
- ETag 304；
- HTML 体积变化；
- 语音资源外置与浏览器加载；
- APK 静态资源布局；
- 版本清单/日期缓存/SSE 帧优化的语法与行为；
- 页面启动；
- 构建。

## 不在范围

- 真机低端机帧率；
- 真实弱网延迟；
- 多用户并发压测；
- APK WebView 的语音文件实际解码；
- CDN/HTTP2。

## 策略

- `curl` 测量生产 `/play` 的压缩 wire size 与响应头。
- `curl`/Node fetch 带 `If-None-Match` 验证304。
- Playwright 加载优化构建，读取 Navigation Timing、transferSize、DCL。
- Playwright 调用 `audio.init()` + `loadVoicePack('female_mature')`，统计语音请求与音频 buffer。
- 解包 APK 检查 assets 文件名/大小。
- 构建1.0.92。
- 页面 pageerror 检查。

## 环境

- Windows / Node26 / Edge / Playwright；
- 生产：192.144.159.220:8080；
- APK：DezhouNight-1.0.92.apk；
- 无真机。

## 用例表

| 编号 | 对应需求 | 步骤 | 预期 |
|---|---|---|---|
| T1 | R1 | curl br `/play` | Content-Encoding=br，wire<300KB |
| T2 | R1 | curl gzip `/play` | Content-Encoding=gzip，wire<300KB |
| T3 | R2 | 带 ETag 请求 | 304，0字节 |
| T4 | R7 | 页面加载语音包 | 24 个 mp3 200，24 个 buffer |
| T5 | R9 | 生产 `/voice/...mp3` | 200，audio/mpeg |
| T6 | R8 | 解包 APK | 192 个 `assets/voice_*.mp3` |
| T7 | AC4 | 查看 dist index | 约1MB |
| T8 | AC7 | pageerror | 空 |
| T9 | AC9 | 构建 | 1.0.92成功 |
| T10 | AC10 | 真机语音 | 未验证 |

## 命令

```powershell
node --check server/server.js
node --check src/audio.js
npm run build
powershell -ExecutionPolicy Bypass -File .\scripts\build-apk.ps1
curl.exe -s -o NUL -w "%{http_code} %{size_download}" -H "Accept-Encoding: br" http://192.144.159.220:8080/play
curl.exe -s -o NUL -w "%{http_code} %{size_download}" http://192.144.159.220:8080/voice/female_mature/check.mp3
```

## 风险与降级

- Brotli 不被支持时自动回退 gzip/identity；
- 压缩失败时 `serveFile` 继续提供未压缩文件；
- 语音外置失败会走系统 TTS fallback，不会让游戏卡死；
- 部署漏传 voice 时页面的语音加载会失败，测试已覆盖生产路由。
