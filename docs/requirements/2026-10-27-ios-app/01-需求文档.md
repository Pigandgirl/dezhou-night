# 01 需求文档：iOS 苹果手机用户版 App

- 日期：2026-10-27（Asia/Shanghai）
- 版本：Web/PWA `1.2.0`；iOS Shell `1.2.0 (1)`
- 范围：iOS 用户可安装、可启动的版本，包含 PWA 与原生 WKWebView 壳
- 状态：代码、自动化测试、未签名 IPA、模拟器验证完成；生产发布与 HTTPS 待外部凭据

## 1. 背景与问题

`德扑之夜` 目前有三个客户端入口：

| 入口 | 现状 | 问题 |
|---|---|---|
| Web `/play` | 单文件 HTML + Three.js，功能完整 | iOS 只能用浏览器打开，像网页不像 App |
| Android APK | WebView 壳，已迭代到 1.1.10 | iOS 无法安装 APK |
| iOS PWA（1.0.36 起） | Safari 可「添加到主屏幕」 | 没有安装引导；Service Worker 作用域是 `/play/`，控制不到 `/play`；没有启动图；HTTP 下没有离线/麦克风 |

用户明确要求「把 iOS 苹果手机用户版本的 app 做出来」。本机是 Windows，
没有 macOS/Xcode，也没有 Apple Developer 账号或服务器 SSH 凭据，因此不能
在本机直接编译、签名并上架 iOS 应用。本需求采用两条可落地路径：

1. **PWA 安装版（面向所有 iPhone 用户）**：Safari → 分享 → 添加到主屏幕，
   全屏启动、独立图标、启动图、安装引导、HTTPS 下离线与麦克风。
2. **原生 WKWebView 壳（面向测试/内测）**：Swift + WebKit，零 CocoaPods，
   在 GitHub Actions 的 macOS 14 runner 上用 Xcode 15.4 编译出 arm64 未签名
   `.ipa`，供 Sideloadly/AltStore 签名安装；同工作流在 iOS 17.5 模拟器启动并截图。

### 1.1 环境事实（本轮实测）

| 事实 | 值 |
|---|---|
| 生产 Web | `http://192.144.159.220:8080/play`，版本 `1.1.10`，HTTP |
| 生产 443 | 关闭（`Test-NetConnection ... -Port 443` = False） |
| 本机 | Windows 11 26200，Node 26.3.1，Edge 149，Python 3.12.10 |
| macOS 构建 | GitHub Actions `macos-14`，macOS 14.8.9，Xcode 15.4 (15F31d)，iOS 17.5 SDK |
| 服务器部署访问 | 无 `DEPLOY_PASS`；`dezhounight_deploy` SSH key 被拒（publickey,password） |
| Apple 签名 | 无 Apple Developer 证书/描述文件/账号 |

## 2. 目标与成功标准

### 2.1 目标

- **G1**：iPhone 用户从 Safari 打开 `/play`，看到明确的「添加到主屏幕」引导，
  安装后从桌面启动，全屏、横屏、带品牌启动图，而不是浏览器标签页。
- **G2**：在 HTTPS 部署后，安装版 PWA 可以离线打开缓存壳，并显示新版本提示；
  麦克风语音满足 iOS 安全上下文要求。
- **G3**：产出一个真实可编译的 iOS 原生壳，CI 能稳定生成未签名 IPA，并能用
  iOS 模拟器证明它能够启动、加载生产牌桌。
- **G4**：把「能装 / 怎么装 / 哪些没验证 / 还缺什么」写清楚，避免把 HTTP 限制、
  未签名包或未上架说成已完成。

### 2.2 成功标准

见第 6 节 AC1–AC15。最低成功线：AC1–AC13 全部通过；AC14/AC15 若因外部凭据
无法完成，必须标记「阻塞」并给出可执行的后续命令，不得标「通过」。

## 3. 用户场景

### 场景 A：普通 iPhone 用户首次访问（Safari）

1. 在 Safari 打开 `http://192.144.159.220:8080/play`（未来为 HTTPS 域名）。
2. 页面加载后 2.6 秒弹出安装引导：点分享 → 添加到主屏幕 → 添加。
3. 用户点「我知道了」或「不再自动提示」；之后仍可在「设置」里重新打开引导。
4. 回到桌面，点「德扑之夜」图标，全屏进入牌桌；启动时显示品牌启动图。

### 场景 B：微信/Chrome/抖音内打开

1. 页面检测到非 Safari 的 iOS 浏览器。
2. 引导标题变为「请用 Safari 打开」，提供复制链接按钮和右上角菜单步骤。
3. 用户复制链接到 Safari 后按场景 A 安装。

### 场景 C：已安装用户再次打开

1. 从主屏幕启动，`navigator.standalone` / `display-mode: standalone` 为真。
2. 不显示安装引导；设置页显示「已从主屏幕启动 · 全屏 App 模式」。
3. 首次从桌面启动会提示一次「桌面 App 模式 · 全屏运行」。

### 场景 D：HTTPS 后的离线/更新

1. 首次打开时 Service Worker 缓存 `/play` 与图标。
2. 断网后仍能从主屏幕打开缓存的牌桌壳，显示离线重试页（若没有缓存）。
3. 发版后，已打开的页面顶部出现「新版本已就绪」，点更新重进牌桌。

### 场景 E：测试同学安装原生壳

1. Windows/macOS 安装 Sideloadly，连接 iPhone，信任电脑。
2. 把 `DezhouNight-unsigned.ipa` 拖入 Sideloadly，用 Apple ID 签名。
3. 手机上信任开发者，从桌面启动原生壳；壳加载生产 `/play`。
4. 沙盒/模拟器截图由 GitHub Actions 自动产出，见 `04-验收报告.md`。

## 4. 需求点

### R1 iOS 可安装的 Web App Manifest

- `/play/manifest.webmanifest` 提供 `id`、`name`、`short_name`、`start_url=/play`、
  `scope=/play`、`display=standalone`、`orientation=landscape`、主题色、图标。
- `index.html` 提供 `apple-mobile-web-app-capable`、状态栏、标题、180×180
  `apple-touch-icon`、`viewport-fit=cover`。
- 服务端 `/play/manifest.webmanifest` 返回 `application/manifest+json`。

### R2 安装引导与再次入口

- iOS Safari（非 standalone）自动弹出一次三步引导；3 天内不重复打扰。
- 「不再自动提示」永久关闭自动弹出。
- 设置弹窗新增「安装到主屏幕」按钮；点击可随时重开引导。
- 非 Safari（微信/QQ/Chrome/抖音等）显示「请用 Safari 打开」及复制链接。
- 引导必须适配 393×852 竖屏，不溢出安全区。

### R3 桌面 App / 原生 App 模式

- 检测 `navigator.standalone`、`display-mode: standalone/fullscreen/minimal-ui`。
- 给 `<html>` 加 `ios`、`ios-standalone` 或 `ios-native` class。
- standalone 下隐藏安装入口，设置页显示「已从主屏幕启动 · 全屏 App 模式」。
- 原生壳注入 `window.__DZ_SHELL__='ios-native'`，隐藏所有安装引导。
- 横屏、安全区、无浏览器边框；保留现有 HUD 的 `env(safe-area-inset-*)`。

### R4 图标与启动图

- 192/512/1024 普通图标、512 maskable 图标、180 apple-touch 图标。
- 24 张 `apple-touch-startup-image`：覆盖 iPhone 430/393/390/428/414/375/320
  与 iPad 1024/820/834/744 的横竖屏，共 12 组设备 × 2 方向。
- 启动图必须包含品牌「德扑之夜」与深色背景，无白屏闪烁。
- 文件全部放在 `/play/icons/`，复用现有服务端路由与部署脚本。

### R5 PWA 外壳、离线与更新

- Service Worker 作用域必须是 `/play`（不是 `/play/`），才能控制 `/play` 本身。
- 服务端 `/play/sw.js` 返回 `Service-Worker-Allowed: /play`。
- 缓存 `/play`、manifest、图标；API/SSE/WebRTC/下载不缓存。
- 断网重载 `/play` 时从缓存启动；没有缓存时给品牌离线页。
- 新版本安装后显示「新版本已就绪」条，点击更新；首次安装不得误报更新。
- 旧 `/play/` 作用域注册要在启动时注销，避免双 SW。

### R6 HTTP/HTTPS 行为

- 只有安全上下文（HTTPS 或 localhost）才注册 SW。
- HTTP 下安装引导必须显示黄色提示：「可安装；离线缓存与麦克风需要 HTTPS」。
- 不得在 HTTP 下假装离线/麦克风可用。
- 原生壳当前允许 HTTP（ATS `NSAllowsArbitraryLoads`）以便加载生产；
  HTTPS 上线后必须改 `DZ_APP_URL` 并移除该例外。

### R7 iOS 原生 WKWebView 壳

- Swift + UIKit + WebKit，最低 iOS 15，iPhone/iPad，横屏。
- 全屏 WKWebView，加载 `DZ_APP_URL`（默认生产 `/play`）。
- 启动屏（`UILaunchScreen`）、AppIcon、Info.plist 中文显示名、版本号。
- 麦克风权限描述、内联媒体播放、`getUserMedia` 所需配置。
- 加载失败显示「暂时进不去牌桌」+ 重试；WebContent 崩溃自动重载。
- 站内链接留在 WebView；站外 http(s)/tel/mailto 交给系统。
- 支持 JS alert/confirm/prompt，避免页面弹窗在原生壳里失效。
- 注入 `__DZ_SHELL__` 与版本；供 Web 端隐藏安装引导。

### R8 macOS CI 构建与制品

- GitHub Actions `macos-14` + XcodeGen + Xcode 15.4。
- 生成 `DezhouNight.xcodeproj`（projectFormat 必须兼容 Xcode 15）。
- 构建 arm64 device archive，打包未签名 IPA，输出 SHA256。
- 在同一 runner 的 iOS 17.5 模拟器安装、启动、截图。
- 上传 GitHub Actions Artifacts；保留 14 天。
- 预留可选签名 Job：配置 Apple 证书/描述文件后导出签名 IPA，供 TestFlight。

### R9 分发与用户路径

- PWA：Safari 打开 `/play` → 添加到主屏幕；不需要 Apple ID。
- 原生未签名包：Sideloadly/AltStore + Apple ID（免费 7 天或开发者账号）。
- 上架/TestFlight：需要 Apple Developer Program（99 美元/年）+ 签名证书。
- 文档必须写清「未签名 IPA 不能直接双击安装」。

### R10 生产发布与 HTTPS

- 把 Web 1.2.0、`sw.js`、manifest、图标/启动图、`server.js`（Service-Worker-Allowed）
  发布到生产。
- 配置 HTTPS（域名 + 证书/反代），把 `PUBLIC_ORIGIN`、`DZ_APP_URL` 改为 HTTPS。
- 重新验证 iPhone 真机的安装、离线、麦克风。
- 该需求依赖服务器部署凭据、域名、TLS；本轮无法自行完成。

## 5. 边界与非目标

- **不做 App Store 上架**：没有 Apple Developer 账号、证书、App Store Connect 配置。
- **不做真机验证**：本轮只有 Edge/WebKit 仿真与 iOS 17.5 模拟器；真机安装、麦克风、
  蓝牙/音频路由未验证。
- **不做生产发布**：没有 `DEPLOY_PASS`，SSH key 被拒；生产仍为 1.1.10/HTTP。
- **不做 HTTPS 证书/域名采购**：需要域名与服务器权限。
- **不改游戏规则、账号、经济、支付、语音协议**。
- **不重建 Android APK**：`android/version.json` 仍为 1.1.10；Web 1.2.0 对 API 向后兼容。
- **不把 WebView 壳包装成「App Store 已上架」**；4.2 最低功能风险在风险章节说明。
- **不承诺 HTTP 下语音可用**；这是 iOS 平台限制，不是代码开关。

## 7. 依赖与风险

| 依赖/风险 | 影响 | 处理 |
|---|---|---|
| 无 macOS/Xcode 本机 | 无法本地编译 iOS | 使用 GitHub Actions `macos-14`（已实测 Xcode 15.4） |
| 无 Apple Developer 证书 | 无法签名/TestFlight/App Store | 产出未签名 IPA；Sideloadly 个人签名；签名 Job 预留 |
| 生产 HTTP + 443 关闭 | iOS 无 SW、无麦克风 | 引导显式提示；原生壳 ATS 例外；HTTPS 后移除 |
| 无服务器部署凭据 | 1.2.0 无法上线，生产仍 1.1.10 | 交付 `deploy_server.py` 命令；待用户提供 `DEPLOY_PASS` |
| WebView 壳内容来自远程 | App Store 4.2 最低功能风险；断网打不开 | 内测/侧载定位；上架前补充原生能力或改审核策略 |
| 真机未验证 | 安装、麦克风、音频路由、刘海安全区可能不同 | 列为未覆盖项；要求真机回归 |
| 免费 Apple ID 7 天过期 | 侧载包需重签 | 文档写明；长期需开发者账号 |
| GitHub 私有构建仓库 | 使用用户 GitHub 账号与 macOS 分钟 | 仅含壳代码；可随时删除；未提交任何密钥 |

## 8. 待确认问题

1. 是否提供服务器 `DEPLOY_PASS`（或 SSH 密钥）以发布 Web 1.2.0 并配置 HTTPS？
2. 是否有可用域名与 TLS 证书/反代（Caddy/Nginx）？没有域名时可用 Cloudflare Tunnel
   做临时验证，但不建议作为长期生产入口。
3. 是否有 Apple Developer 账号/证书/描述文件？有则可把可选签名 Job 打开，
   产出 TestFlight 包；没有则只能 Sideloadly 个人签名。
4. iOS 原生壳的定位是「内测/侧载」还是「必须上架」？若必须上架，需要先补原生功能
   以降低 4.2 审核风险。
