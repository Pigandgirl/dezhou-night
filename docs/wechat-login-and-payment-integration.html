Integration Guide

微信登录 与 微信支付（真实收款）接入文档

面向「德扑之夜」当前架构：Node 零依赖房间服务（server/server.js）+ 单文件 Web 客户端（Vite 打包，Android WebView 与 /play 共用）+ 自建手机号账户体系（src/account.js）。

微信开放平台 · 网站应用 / 移动应用 微信支付 APIv3 Native / APP / JSAPI RSA-SHA256 + AES-256-GCM
先看结论：微信登录与微信支付都不是“填个 AppID 就能用”，全部依赖企业主体资质 + 已备案域名 + HTTPS + 审核通过的应用/商户号。当前服务是 http://192.144.159.220:8080（IP + 明文 HTTP），微信侧无法配置该回调地址。必须先补齐第 1、2 节，代码才具备联调条件。

1. 资质与前置条件

1.1 微信登录所需

项目要求产出
微信开放平台账号企业主体（个体户亦可），需营业执照、对公账户打款验证开放平台开发者账号
网站应用用于电脑端 /play 扫码登录；需已备案域名、网站可访问、类目说明AppID / AppSecret，审核周期约 1–7 个工作日
移动应用用于 Android APK 内微信登录；需填包名 com.dezhounight.poker 与签名 MD5同一开放平台下的 AppID（移动应用独立 AppID）
开放平台账号绑定网站应用与移动应用绑定到同一开放平台账号unionid 跨应用统一，用于账号合并
关键限制：扫码登录（snsapi_login）拿不到手机号，只能拿到 openid / unionid / 昵称 / 头像。若要“微信一键登录且自动带手机号”，必须额外具备已认证服务号/小程序并使用「手机号快速验证组件」（企业主体 + 按次计费）。本项目建议：微信登录后仍要求绑定一次手机号（复用现有账户体系），或允许纯微信账户无手机号参与。

1.2 微信支付所需

项目要求产出
微信支付商户号企业/个体户，营业执照、法人身份证、对公账户、经营类目（游戏/虚拟道具需相应资质）mchid（10 位）
AppID 绑定商户号需绑定网站应用 / 移动应用 AppID（服务商模式则绑定服务商 AppID）可用 appid + mchid 下单
APIv3 密钥商户平台 → 账户中心 → API 安全 → 设置 APIv3 密钥（32 字节）用于回调报文 AES-256-GCM 解密
商户 API 证书申请后下载 apiclient_key.pem、apiclient_cert.pem请求签名（私钥）+ 证书序列号 serial_no
微信支付平台证书 / 公钥用于验证回调签名；新商户建议直接用「微信支付公钥」模式wechatpay_public_key.pem 或平台证书
APP 支付开通移动应用需在开放平台审核通过并上线，商户平台开通「APP 支付」Android 可拉起微信收款

1.3 主体类型选择：能不能用“个人”

结论：自然人不可以，最低门槛是“个体工商户”。微信支付与微信开放平台对“个人（自然人）”均不开放完整能力，具体差异如下：

主体微信登录（开放平台）Native 支付（电脑端）APP 支付（安卓端）可用性
自然人个人不能认证，无法申请网站应用 / 移动应用仅“小微商户 / 个人卖家”通道，需服务商进件不支持不可用
小微商户 / 个人卖家不适用（无开放平台登录能力）支持不支持不适用于本项目
个体工商户支持（需开发者资质认证）支持支持推荐
企业支持支持支持推荐
“个人卖家 / 小微商户”为什么走不通：
  • 只能由微信支付服务商通过 API 进件，不能自己在商户平台注册；材料需身份证、结算银行卡，以及门店门口照 + 店内环境照。
  • 支付权限仅 JSAPI / Native / 付款码，不含 APP 支付，APK 内无法拉起微信付款。
  • 官方明确仅限线下行业（餐饮、线下零售、居民生活服务、休闲娱乐、交通出行等），不支持线上直播、游戏等行业，一经发现可关闭支付权限。
  • 微信开放平台开发者资质认证要求非个人主体，自然人无法申请网站应用/移动应用的微信登录。
建议路径（个体户）：注册个体工商户（各地可线上办理，经营范围写“网络技术服务 / 软件开发 / 信息技术服务”）→ 以个体户主体注册微信开放平台并完成开发者资质认证（约 300 元/年）→ 申请微信支付普通商户号 → 开通 Native + APP 支付（个体户不支持 H5 支付，本项目用不到）→ 用个体户资质完成域名 ICP 备案。整条链路与文档第 3–13 章完全一致。
真正的审核风险不在主体，而在类目：本项目为德州扑克 + 充值次数/积分，属于“游戏 / 虚拟币充值”类目。微信支付对游戏类商户通常要求版号、网络文化经营许可证等资质，棋牌/博彩类产品被拒概率高；即便个体户进件成功，也可能因风控被冻结结算。主体只是第一道门，类目合规才是决定能否长期收款的关键。

2. 域名与 HTTPS（当前最大阻塞项）

微信登录的 redirect_uri、支付的 notify_url 都必须是公网可访问的已备案域名，不能是 IP，不建议带端口。当前服务直接暴露 192.144.159.220:8080，需先完成：

  1. 准备域名（如 poker.example.com），在腾讯云完成 ICP 备案（大陆服务器强制）。
  2. 用 Nginx/Caddy 监听 443，配置证书（腾讯云免费证书即可），反代到 127.0.0.1:8080。同机 80 端口已被 camelup.service 占用，不要动它。
  3. 在开放平台「网站应用 → 授权回调域」填写 poker.example.com（只填域名，不带协议与路径）。
  4. 把客户端在线基址从 http://192.144.159.220:8080 改为 https://poker.example.com（构建时 UPDATE_BASE）。
  5. 微信支付 notify_url 配为 https://poker.example.com/api/pay/notify，并确认外网可直接 POST 到达（不要加鉴权头、不要重定向）。
# /etc/nginx/conf.d/poker.conf 参考
server {
  listen 443 ssl http2;
  server_name poker.example.com;

  ssl_certificate     /etc/ssl/poker/fullchain.pem;
  ssl_certificate_key /etc/ssl/poker/privkey.pem;

  location /api/pay/notify {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    client_max_body_size 256k;
  }

  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    # SSE 必须关闭缓冲
    proxy_buffering off;
    proxy_read_timeout 3600s;
  }
}

3. 电脑端扫码登录（网站应用）

适用于 /play。全流程无需 SDK，纯 HTTP。

  1. 服务端生成授权地址，前端渲染二维码（可直接内嵌微信官方二维码页 open.weixin.qq.com/connect/qrconnect，也可用 qrconnect 返回的页面）。
  2. 用户扫码确认后，微信带着 code 重定向到你的回调地址。
  3. 服务端用 code 换 access_token 与 openid。
  4. 服务端拉取用户信息（昵称、头像、unionid）。
  5. 按 unionid/openid 查找或创建本站账户，签发本站 token（复用现有 30 天登录态）。
授权地址（前端跳转或生成二维码内容）：
https://open.weixin.qq.com/connect/qrconnect
  ?appid=WX_WEB_APPID
  &redirect_uri=https%3A%2F%2Fpoker.example.com%2Fapi%2Fauth%2Fwechat%2Fcallback
  &response_type=code
  &scope=snsapi_login
  &state=RANDOM_CSRF_TOKEN
#wechat_redirect

① code 换 token（服务端）
GET https://api.weixin.qq.com/sns/oauth2/access_token
    ?appid=WX_WEB_APPID&secret=WX_WEB_SECRET&code=CODE&grant_type=authorization_code
→ { access_token, expires_in, refresh_token, openid, scope, unionid? }

② 拉取用户信息（服务端）
GET https://api.weixin.qq.com/sns/userinfo?access_token=ACCESS_TOKEN&openid=OPENID&lang=zh_CN
→ { openid, nickname, sex, headimgurl, unionid, ... }
state 必须校验：授权前把随机 state 写入短期缓存（如 5 分钟有效），回调时比对，防止 CSRF 与登录劫持。回调完成后立即签发一次性 ticket 再跳回前端，避免把本站 token 暴露在 URL 中。

4. Android 微信登录（移动应用）

APK 内是 WebView，不能在网页里直接完成微信 App 授权。方案：H5 通过 NativeBridge 调用原生微信 SDK，原生把 code 回传 H5，再由服务端换 token。

  1. 开放平台创建「移动应用」，填写应用包名 com.dezhounight.poker 与签名 MD5（用打包 keystore 计算，无冒号、小写）。
  2. 引入微信 SDK（AAR）：com.tencent.mm.opensdk:wechat-sdk-android:6.8.0。当前工程是手工 aapt2/d8 打包，需把 AAR 解出的 classes.jar 参与 d8，并合并其 AndroidManifest 的 WXEntryActivity 声明。
  3. 新增 wxapi/WXEntryActivity.java（包名固定为 你的包名.wxapi.WXEntryActivity），在 onResp 中取 SendAuth.Resp.code。
  4. 在 MainActivity 注册 IWXAPI，暴露 NativeBridge.wechatLogin()，把 code 通过 WebView.evaluateJavascript 回传。
  5. H5 收到 code 后调用 /api/auth/wechat/login（与网页端共用服务端逻辑）。
// app/src/main/java/com/dezhounight/poker/wxapi/WXEntryActivity.java
package com.dezhounight.poker.wxapi;

import android.app.Activity;
import android.os.Bundle;
import com.tencent.mm.opensdk.modelbase.BaseReq;
import com.tencent.mm.opensdk.modelbase.BaseResp;
import com.tencent.mm.opensdk.modelmsg.SendAuth;
import com.tencent.mm.opensdk.openapi.IWXAPI;
import com.tencent.mm.opensdk.openapi.IWXAPIEventHandler;
import com.tencent.mm.opensdk.openapi.WXAPIFactory;

public class WXEntryActivity extends Activity implements IWXAPIEventHandler {
    private IWXAPI api;

    @Override protected void onCreate(Bundle b) {
        super.onCreate(b);
        api = WXAPIFactory.createWXAPI(this, "WX_APP_APPID", false);
        api.registerApp("WX_APP_APPID");
        api.handleIntent(getIntent(), this);
    }

    @Override public void onReq(BaseReq req) { finish(); }

    @Override public void onResp(BaseResp resp) {
        if (resp instanceof SendAuth.Resp) {
            SendAuth.Resp r = (SendAuth.Resp) resp;
            // r.errCode == 0 时 r.code 为授权码
            MainActivity.deliverWechatCode(r.errCode, r.code, r.state);
        }
        finish();
    }
}
<!-- AndroidManifest.xml 追加 -->
<activity
    android:name=".wxapi.WXEntryActivity"
    android:exported="true"
    android:taskAffinity="com.dezhounight.poker"
    android:launchMode="singleTask" />
签名校验：微信会校验 APK 的实际签名 MD5 是否与开放平台填写一致。更换 keystore 后必须回平台更新签名，否则登录/支付一律返回 errCode=-1。

5. 账号合并与数据模型

现有账户以手机号为主键（store.users 的 key 为 phone）。建议扩展为“手机号 + 微信身份”多登录方式：

user = {
  phone,                 // 仍保留；微信新用户可为空字符串（或生成占位）
  name, pwdHash,         // 现有字段
  wechat: {              // 新增
    openId,              // 单应用内唯一
    unionId,             // 跨应用统一（需绑定开放平台账号）
    nickname, avatar,    // 仅展示用，需自行做内容安全处理
    boundAt
  },
  points, todayPoints, plays, totalRecharge, honors, tokens
}

// 索引：wechat.unionId → phone，openId → phone（内存 Map 或持久化对象）
场景处理规则
微信首次登录创建账户，生成昵称（微信昵称截断 12 字），赠送 100 积分；提示绑定手机号以便找回
已绑定微信的手机号登录沿用原账户，不重复发新手积分
微信 unionId 已绑定其他账户直接登录原账户；若当前已登录另一账户，提示“是否切换”
同一微信绑定第二个手机号拒绝，需先解绑（防止多账户刷新手积分）
解绑微信要求短信/密码二次验证；解绑后仍可用手机号登录

async function wechatExchangeCode(code, appid, secret) {
  const q = new URLSearchParams({
    appid, secret, code, grant_type: 'authorization_code',
  });
  const res = await fetch(`https://api.weixin.qq.com/sns/oauth2/access_token?${q}`);
  const data = await res.json();
  if (!data.access_token) throw new Error(data.errmsg || 'wechat token failed');
  const info = await (await fetch(
    `https://api.weixin.qq.com/sns/userinfo?access_token=${data.access_token}` +
    `&openid=${data.openid}&lang=zh_CN`
  )).json();
  return {
    openId: data.openid,
    unionId: data.unionid || info.unionid || '',
    nickname: String(info.nickname || '微信玩家').slice(0, 12),
    avatar: String(info.headimgurl || ''),
  };
}

8. 下单与回调时序

  1. 客户端选择套餐（1 元 / 6 元 / 30 元 / 98 元）。金额与到账内容必须由服务端按套餐 ID 决定，不接受前端传金额。
  2. 服务端创建订单（out_trade_no 唯一，amount.total 单位为分），调用微信下单接口。
  3. 返回 code_url（Native）或 prepay_id（APP）给客户端。
  4. 用户支付成功，微信向 notify_url POST 加密回调。
  5. 服务端：验签 → 解密 → 校验金额与订单号 → 幂等发货（加次数/积分）→ 返回 200。
  6. 客户端轮询/查询订单状态（Native）或收到支付回调后刷新账户；APP 支付由 WXPayEntryActivity 回调结果。
  7. 若回调丢失：定时任务调用查单接口补单（见第 12 节）。

9. APIv3 服务端实现骨架（零依赖，Node crypto）

9.1 请求签名与调用

const crypto = require('crypto');
const fs = require('fs');

const MCH_ID = process.env.WX_MCH_ID;
const SERIAL_NO = process.env.WX_MCH_SERIAL_NO;      // 商户证书序列号
const PRIVATE_KEY = fs.readFileSync(process.env.WX_MCH_KEY_PATH, 'utf8');

function buildAuth(method, urlPath, body) {
  const timestamp = Math.floor(Date.now() / 1000).toString();
  const nonce = crypto.randomBytes(16).toString('hex');
  const message = `${method}\n${urlPath}\n${timestamp}\n${nonce}\n${body}\n`;
  const signature = crypto.sign('RSA-SHA256', Buffer.from(message), PRIVATE_KEY).toString('base64');
  return `WECHATPAY2-SHA256-RSA2048 mchid="${MCH_ID}",nonce_str="${nonce}",` +
         `signature="${signature}",timestamp="${timestamp}",serial_no="${SERIAL_NO}"`;
}

async function wechatPay(method, urlPath, payload) {
  const body = payload ? JSON.stringify(payload) : '';
  const res = await fetch(`https://api.mch.weixin.qq.com${urlPath}`, {
    method,
    headers: {
      Authorization: buildAuth(method, urlPath, body),
      Accept: 'application/json',
      'Content-Type': 'application/json',
      'Wechatpay-Serial': process.env.WX_PAY_PUBLIC_KEY_ID || '',
      'User-Agent': 'dezhounight/1.0',
    },
    body: body || undefined,
  });
  const text = await res.text();
  const data = text ? JSON.parse(text) : {};
  if (!res.ok) throw new Error(`wechat pay ${res.status}: ${data.message || text}`);
  return data;
}

// Native 扫码下单
function createNativeOrder({ orderNo, fen, description, notifyUrl }) {

9.2 回调验签与解密

const PAY_PUBLIC_KEY = fs.readFileSync(process.env.WX_PAY_PUBLIC_KEY_PATH, 'utf8');

function verifyNotify(headers, rawBody) {
  const ts = headers['wechatpay-timestamp'];
  const nonce = headers['wechatpay-nonce'];
  const signature = headers['wechatpay-signature'];
  const serial = headers['wechatpay-serial'];
  if (!ts || !nonce || !signature) return false;
  // 防重放：时间戳 5 分钟内
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false;
  if (process.env.WX_PAY_PUBLIC_KEY_ID && serial !== process.env.WX_PAY_PUBLIC_KEY_ID) return false;
  const message = `${ts}\n${nonce}\n${rawBody}\n`;
  return crypto.verify('RSA-SHA256', Buffer.from(message), PAY_PUBLIC_KEY,
    Buffer.from(signature, 'base64'));
}

function decryptResource(resource) {
  const key = Buffer.from(process.env.WX_API_V3_KEY, 'utf8');       // 32 字节
  const data = Buffer.from(resource.ciphertext, 'base64');
  const authTag = data.subarray(data.length - 16);
  const ciphertext = data.subarray(0, data.length - 16);
  const decipher = crypto.createDecipheriv('aes-256-gcm', key, Buffer.from(resource.nonce, 'utf8'));
  decipher.setAuthTag(authTag);
  decipher.setAAD(Buffer.from(resource.associated_data || '', 'utf8'));
  return JSON.parse(Buffer.concat([decipher.update(ciphertext), decipher.final()]).toString('utf8'));
}

// 回调路由：必须读取原始 body（不要先 JSON.parse）
// POST /api/pay/notify
async function handleNotify(req, res, rawBody) {
  if (!verifyNotify(req.headers, rawBody)) {
    res.writeHead(401, { 'Content-Type': 'application/json' });
    return res.end(JSON.stringify({ code: 'FAIL', message: '签名验证失败' }));
  }
  const payload = JSON.parse(rawBody);
  const data = decryptResource(payload.resource);   // { out_trade_no, trade_state, amount, ... }
  if (data.trade_state !== 'SUCCESS') {
    res.writeHead(200); return res.end('');         // 非成功状态按要求应答
  }
  await fulfilOrder(data.out_trade_no, data.amount.total);   // 幂等发货
  res.writeHead(200); res.end('');
}
原始报文：验签必须使用未解析的原始 JSON 字符串。现有 readBody() 会直接 JSON.parse，需为 /api/pay/notify 单独读取 Buffer 并保留原串，否则验签必然失败。

11. 订单表与发货幂等

规则说明
服务端定价套餐 ID → 金额/到账内容写死在服务端，前端只能传 packId
订单号唯一DN + 时间戳 + 随机；同一订单重复下单返回原 codeUrl
金额核对回调金额必须等于订单金额，不等则拒绝发货并告警
幂等发货if (order.status === 'delivered') return; 发货后原子写 delivered；并发用单线程队列或文件锁
超时关单15 分钟未支付调用 /v3/pay/transactions/out-trade-no/{no}/close
归属校验回调中的 mchid/appid 必须与配置一致，防跨商户伪造
async function fulfilOrder(orderNo, paidFen) {
  const order = store.orders.get(orderNo);
  if (!order) return;
  if (order.status === 'delivered') return;                 // 幂等
  if (paidFen !== order.fen) { console.error('[pay] 金额不符', orderNo, paidFen); return; }
  const user = store.users.get(order.phone);
  if (!user) return;
  user.plays = (user.plays || 0) + order.granted.plays;
  user.points = (user.points || 0) + order.granted.points;
  user.todayPoints = (user.todayPoints || 0) + order.granted.points;
  user.totalRecharge = (user.totalRecharge || 0) + order.yuan;
  order.status = 'delivered';
  order.deliveredAt = Date.now();
  saveStore();
}

12. 退款、对账与补单

  • 补单：每 60 秒扫描 status=created 且超过 2 分钟的订单，调用查单接口 GET /v3/pay/transactions/out-trade-no/{no}?mchid=，trade_state=SUCCESS 时按回调同样逻辑发货。
  • 退款：POST /v3/refund/domestic/refunds，传 out_trade_no、out_refund_no、amount.refund/ total/currency；退款成功后必须回收已发放的次数与积分（允许扣成 0，不允许负数），并在账单中留痕。
  • 对账：每日下载 /v3/bill/tradebill?bill_date=YYYY-MM-DD&bill_type=ALL，逐笔比对订单表，差异告警。
  • 日志：订单号、金额、状态可留；不记录 openid、手机号全量、证书与密钥。

16. 合规风险提示（务必先评估）

  • 棋牌类目资质：德州扑克属于棋牌类游戏，境内运营通常需要游戏版号、文网文/ICP 相关资质、实名与防沉迷；应用商店上架也会审核玩法与付费点。
  • 涉赌红线：只要“充值 → 参与牌局 → 积分/筹码可提现或兑换实物/变现”，就可能被认定为赌博或变相赌博。当前设计是“充值买次数 + 积分排行”，务必保证：积分不可提现、不可转让、不可兑换实物，筹码纯虚拟且不可交易，并显著声明“虚拟道具、仅供娱乐”。
  • 未成年人保护：需实名认证与限额，禁止未成年人充值；支付前应做年龄与实名校验。
  • 苹果端限制：iOS 上虚拟道具需走 App 内购买（IAP），微信支付不可用于购买虚拟币；当前只有 Android 与 Web，暂不涉及。
  • 退款与消费者权益：需有明确的虚拟道具退款规则、客服入口与订单查询，避免投诉与支付通道风控。
建议：在上线收费前完成一次法务评估，并把“充值获得的次数/积分”定义为不可退款、不可转让的虚拟服务凭证（或保留未使用部分的退款通道），同时在页面显著位置公示规则。本文件仅提供技术接入方案，不构成法律意见。
